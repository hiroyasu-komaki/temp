# 第9章　導入ロードマップ

> **この章の位置づけ**：CSF 導入済みの組織が、AIセキュリティのケイパビリティを段階的に導入し、ガバナンスを安定させるまでの計画を示す
> **対象読者**：経営層・CISO、セキュリティガバナンス担当

## 要旨

- 3段階で進める：**Phase 1 ガバナンス拡張と基本対策の同時開始** → **Phase 2 ユースケース別評価の高度化** → **Phase 3 対応表による統合管理と監査運用**。
- 各 Phase は「NIST（ガバナンス層）」と「OWASP（技術対策層）」を同時に進め、片方だけが先行しないようにする。
- 外部の枠組みは動いている（AI RMF 改訂、Cyber AI Profile、COSAiS）。追跡対象として管理し、正式版が出たら差し替える。

## 9.1 全体像

| Phase | 目的 | NIST（ガバナンス層） | OWASP（技術対策層） | 完了の目安 |
|---|---|---|---|---|
| 1 | 把握と基本の統制を同時に始める | AI利用方針、AI資産台帳、審査プロセス（暫定） | 最優先リスクのチェックリスト適用 | 全生成AIシステムが台帳に載り、新規案件が審査を通る |
| 2 | 構成に応じた評価にする | Tier 別審査、独立評価、残留リスクの受容ルール | RAG・エージェントの追加チェック、レッドチーミング | High 案件がすべてレッドチーミング済み |
| 3 | 報告と改善を回す | 機能別・リスク別の経営報告、監査対応 | 対応表による集約、ギャップ分析 | 経営報告と現場記録が同じデータから出ている |

## 9.2 Phase 1：ガバナンス拡張と基本対策の同時開始

| 区分 | 実施事項 | 根拠 |
|---|---|---|
| NIST | 生成AI利用方針の制定（入力禁止データ、承認が必要な操作、利用してよいサービス） | GOVERN 1.1、GV.OC-01 |
| NIST | **AI資産台帳**の作成。既存の資産台帳（ID.AM-08）と統合し、AI 600-1 GV-1.6-003 の項目（基盤モデルとバージョン、データの来歴、既知の問題、ヒューマンオーバーサイトの役割、知的財産・機密データの扱い）を追加 | GOVERN 1.6 |
| NIST | 既存の供給者管理（GV.SC）に、モデル・データ・AIサービスの提供者を追加。利用規約で学習不使用・保持条件を確認 | GOVERN 6.1、MANAGE 3.1 |
| NIST | 暫定の審査プロセス（第8章の事前分類5問のみで Tier を判定） | GOVERN 1.3 |
| OWASP | 全案件共通の最優先チェック：**LLM01 プロンプトインジェクション、LLM02 機密情報の漏洩、LLM10 不適切な出力処理**（＋エージェントがあれば LLM03 過剰な権限） | — |
| OWASP | 既存の監視（DE.CM-01）にプロンプト・ツール呼出・トークン消費のログを追加 | — |

## 9.3 Phase 2：ユースケース別評価の高度化

| 区分 | 実施事項 | 根拠 |
|---|---|---|
| NIST | Tier 別審査の本格運用。High は専門部会、残留リスクは経営層が受容 | GOVERN 2.3、MANAGE 1.4 |
| NIST | 第一線の開発者以外による独立評価の体制 | MEASURE 1.3 |
| NIST | 停止・廃止の手順と責任者の明確化 | MANAGE 2.4、GOVERN 1.7 |
| OWASP | RAG の追加チェック：**LLM09 ベクトル・埋め込みの弱点**（検索前の認可、インデックス分離）、LLM07 誤情報（出典表示、根拠性評価） | MEASURE 2.5 |
| OWASP | エージェントの追加チェック：**Agentic Top 10 全体**、Rule of Two、完全仲介、サーキットブレーカー（LLM06）、MCPサーバの審査（ASI04） | MAP 4.1 |
| OWASP | High 案件の**レッドチーミング**（防御仕様を開示した適応型攻撃、漏洩・目標乗っ取りシナリオ） | MEASURE 2.7 |

## 9.4 Phase 3：対応表による統合管理と監査運用

| 区分 | 実施事項 | 根拠 |
|---|---|---|
| NIST | AI RMF 機能別・AI 600-1 リスク別の経営報告（第8章 8.6） | GOVERN 4.2 |
| NIST | インシデントの通知・追跡と、既知の問題の台帳への反映 | MANAGE 4.3 |
| NIST | 年次のプロファイル見直し（現状プロファイルと目標プロファイルの差分で次年度計画を立てる） | AI RMF 第6章（プロファイル） |
| OWASP | 案件の回答を対応表（Top 10 付録A、Crosswalk）で集約し、ダッシュボード化 | — |
| OWASP | Crosswalk の Score 機能で、CSF 2.0・ISO/IEC 27001 等の実装状況からギャップを確認 | — |
| OWASP | OWASP リスト改訂時の差分反映（チェック項目・設問の更新） | MEASURE 4.2 |

## 9.5 外部動向の追跡

| 対象 | 2026-10 時点の状況 | 正式版が出たときの対応 |
|---|---|---|
| NIST AI RMF 改訂版 | 改訂中（AI 行動計画に基づく）。未公開 | カテゴリ・サブカテゴリの番号と表現の変更を第2章・第6章・第8章に反映 |
| NIST Cyber AI Profile（IR 8596） | 準備草案（2025-12）。初期公開草案を 2026 年中に予定 | 第6章の CSF 対応を、Crosswalk から Cyber AI Profile に置き換える |
| NIST COSAiS | コンセプト（2025-08）、予測AI版アウトライン（2026-01） | 生成AI・エージェント版が出たら、第7章の対策を SP 800-53 の管理策に対応付ける |
| OWASP LLM Top 10 | 2026年版（v1.0, 2026-08-04） | 次版で順位・項目が変われば第4章と設問を更新 |
| OWASP Agentic Top 10 | 2026年版（2025-12-09） | 同上（第5章） |
| OWASP GenAI Security Crosswalk | v4.0.0（2026-08-28）、継続更新。多くの行が未レビュー | 査読済みの行が増えたら、第6章の注記を見直す |
| AI事業者ガイドライン | 第1.2版（2026-03-31）。AIエージェントの本格的な扱いは次の改訂に持ち越し | 国内の説明責任の基準として第6章 6.7 を更新 |

## この章の結論

- Phase 1 では「台帳」と「最優先3リスク」を同時に始め、把握と統制を並行して立ち上げる。
- Phase 2 で構成に応じた評価とレッドチーミングを入れ、Phase 3 で経営報告と現場記録を同じデータでつなぐ。
- 外部の枠組みは草案・改訂中のものが多いため、追跡対象として管理し、正式版で差し替える。
