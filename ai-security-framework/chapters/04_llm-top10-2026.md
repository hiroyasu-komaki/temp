# 第4章　OWASP Top 10 for LLM Applications 2026

> **この章の位置づけ**：すべての生成AI案件に適用する10リスクについて、定義・発生パターン・主要な対策を示す
> **対象読者**：案件担当、アーキテクト、開発・運用担当、セキュリティレビュー担当

## 要旨

- 10リスクは「入力の境界（LLM01）」「データの境界（LLM02, 08, 09）」「権限と行動（LLM03, 06）」「部品と学習の完全性（LLM04, 05）」「出力の信頼性と処理（LLM07, 10）」の5群に整理できる。
- 2026年版の対策は、**防ぐ対策**と**被害を限定する対策**を明確に分けている。プロンプトインジェクションのように確実な防止策がないリスクでは、後者が実質的な防御線になる。
- 各リスクは単独で起きるより連鎖する。典型は「間接プロンプトインジェクション（LLM01）→ 過剰な権限による外部送信（LLM03）→ 出力経由のデータ持ち出し（LLM10）」である。

## 4.1 一覧

| ID | リスク | 一言でいうと | 群 |
|---|---|---|---|
| LLM01 | Prompt Injection（プロンプトインジェクション） | 入力がモデルの振る舞いを開発者の意図外に変える | 入力の境界 |
| LLM02 | Sensitive Information Disclosure（機密情報の漏洩） | 許可されていない経路で機密データが露出する | データの境界 |
| LLM03 | Excessive Agency（過剰な権限） | 誤った・操作された出力が、損害を伴う行動につながる | 権限と行動 |
| LLM04 | Supply Chain（サプライチェーン） | 第三者のモデル・データ・アダプタ・基盤が改ざん・汚染される | 部品の完全性 |
| LLM05 | Data and Model Poisoning（データ・モデルのポイズニング） | 学習・埋め込み・検索データが汚染され、振る舞いが歪む | 学習の完全性 |
| LLM06 | Unbounded Consumption（無制限のリソース消費） | 推論の濫用でサービス停止・高額請求・モデル複製が起きる | 権限と行動 |
| LLM07 | Misinformation（誤情報） | もっともらしい誤りが信頼され、判断や行動に使われる | 出力の信頼性 |
| LLM08 | Hidden Context Exposure（隠されたコンテキストの露出） | システムプロンプトやツール定義が抽出・推測される | データの境界 |
| LLM09 | Vector and Embedding Weaknesses（ベクトル・埋め込みの弱点） | 類似検索の仕組みを突いて漏洩・汚染・妨害する | データの境界 |
| LLM10 | Improper Output Handling（不適切な出力処理） | 出力を検証せず下流に渡し、XSS・SQLi・RCE を招く | 出力の処理 |

## LLM01　プロンプトインジェクション

**定義**：ユーザー入力、検索結果、ツール出力、画像・音声・動画、推論過程、永続メモリなどの入力が、開発者の意図しない形でモデルの振る舞いを変える脆弱性。LLMは「指示」と「データ」を同じトークン列として扱うため、パラメータ化クエリに相当する確実な分離手段がない。

**被害を大きくする3つの性質**：①コンテキストの混在（すべての入力が信頼境界なしに1本の列になる）、②メモリの永続性（RAG・メモリへの注入が以後の全セッションを汚染する）、③エージェント実行（出力がツール呼出を動かし、被害がツールの届く範囲まで広がる）。

**種類**

| 種類 | 内容 |
|---|---|
| 直接 | ユーザー（または攻撃者）が入力で振る舞いを変える。脱獄（ジェイルブレイク）はその一部。悪意のない貼り付けによる「意図しない注入」も含む |
| 間接 | Webページ、文書、メール、ツール応答、RAGの検索結果、画像、MCPサーバの出力などに埋め込まれた指示が実行される。供給元の信頼度で「非信頼／半信頼／信頼」に分けて考える |

**典型例**：検索コンテンツ経由の注入、社内の信頼された経路（課題管理・問い合わせフォーム）に仕込まれた指示をユーザー権限のエージェントが実行、画像への不可視な指示の埋め込み、不可視Unicode文字による指示の密輸とデータ持ち出し、メモリ・RAGコーパスの汚染、多言語・符号化による検知回避。

**主要な対策**（単独で十分なものはなく、多層で適用する）

- 防止率を上げる対策：システムプロンプトで役割と許可・禁止を宣言的に定義／出力スキーマを厳格に定め、アプリ側のコードで構造検証／全モダリティ（テキスト・画像・音声）の境界でフィルタ／不可視文字（タグ文字・異体字セレクタ・ゼロ幅文字）を取り込み時と描画時に除去／外部コンテンツを出所付きの別チャネルで渡す
- **被害を限定する対策（攻撃者に適応されても残る）**：資格情報と状態変更の能力はモデルではなくアプリ側に置き、決定論的なポリシーエンジンで実行時に再検証／特権的・不可逆・外部に見える操作の前に、実際に実行される内容をそのまま示して人が承認／メモリへの書き込みを特権操作として扱う／MCPサーバ・ツールのバージョン固定と署名検証
- **Rule of Two**：(A)非信頼入力、(B)機密データ、(C)状態変更・外部通信 の3つを同時に持つエージェントは高リスクとし、操作ごとの人の承認を必須とする。2つを持つ構成は残存リスク評価を行う（第8章の分類で使用）
- **適応型攻撃者を想定した検証**：防御仕様を開示したうえでレッドチーミングを行う。静的テストでの攻撃成功率ほぼ0%が、適応型攻撃では大半の防御で90%超になった研究がある

**関連**：ASI01, ASI02, ASI03, ASI05, ASI06, ASI08, ASI09／AI 600-1：情報セキュリティ（主）

## LLM02　機密情報の漏洩

**定義**：機密・規制対象・特権・営業上の秘密データが、データ主体や管理者が許可していない経路で露出すること。最終回答だけでなく、ツール呼出の引数、推論トレース、検索されたチャンク、ログ・テレメトリ、埋め込み、応答時間やトークン長などの観測可能な特性もすべて漏洩経路になる。

**発生する4つの局面**：学習時（記憶と再現）、推論時（システムプロンプト・RAGチャンク・他セッションのデータの露出）、パイプライン時（ファインチューニング・蒸留・ログ基盤への移動）、観測時（暗号化通信のトークン長や応答時間から内容を推測）。

**事故の2大要因**：①**上流の過剰共有**（権限設定の甘いドライブやナレッジベースをRAGに接続し、モデルが「設計どおり」機密を検索する。直すべきはモデルでなくデータ側）、②**残留**（重み・埋め込み・アダプタに入ったデータは、元データ削除後も抽出されうる）。

**主要な対策**（DSGAI の段階構造に沿う）

| 段階 | 対象 | 主な対策 |
|---|---|---|
| 基礎（全案件） | すべて | コーパスの出所管理・分類・重複排除／外部提供者へは業務に必要な項目だけ送る／**検索の前に認可**（インデックス照会の中で文書・チャンク単位の権限を適用）／システムプロンプトに秘密情報を置かない／正規表現だけでなく分類器で無害化／ユーザー・セッション単位のクエリ上限／ログ・トレースの無害化と、学習不使用・保持なしの技術的な強制 |
| 強化（規制・高機密） | 規制データ等 | ベクトルストアの暗号化と専用ACL、エクスポート制限／対数確率・確信度の非公開化／推論トレースを出力として分類・秘匿／AI対応の監査ログをSIEMへ、DLP・AI-SPMの継続運用／個別に許可された情報源の組合せで禁止された結論が出ないよう結合ポリシーを適用 |
| 高度（機密・高標的） | 特に重要な業務 | コンフィデンシャルコンピューティング／元データ・埋め込み・チェックポイント・アダプタにまたがる検証可能な消去／漏洩レッドチーミングをリリース判定の条件にする |

**関連**：ASI06／AI 600-1：データプライバシー（主）、情報セキュリティ（主）

## LLM03　過剰な権限（Excessive Agency）

**定義**：LLMの予期しない・曖昧な・操作された出力に応じて、損害を伴う行動が実行されてしまう脆弱性。誘因はハルシネーション（作話）とプロンプトインジェクションの両方で、**原因が何であれ「行動できてしまう」こと自体が問題**とされる。

**根本原因**

| 原因 | 例 |
|---|---|
| 過剰な機能 | 文書を読むだけでよいのに、使っているツールに更新・削除機能もある／開発時に試したツールが残っている／特定のシェルコマンドだけ実行するはずのツールが他のコマンドも通す |
| 過剰な権限 | 読み取り用ツールのDB接続IDに更新・削除権限がある／個人の文書を読むツールが全ユーザーの文書にアクセスできる汎用特権IDで接続する |
| 過剰な自律性 | 文書の削除などの重要操作を確認なしに実行する |

**主要な対策**

- 防ぐ対策：ツールの数を最小化／ツールの機能を最小化／シェル実行やURL取得のような汎用ツールを避け、目的別の細かいツールにする（入力スキーマを厳格に）／ツールの権限を最小化／**ユーザーのコンテキストで実行**（OAuth等で最小スコープ。多段の呼出でも元のユーザーの認可範囲を引き継ぐ）／重要操作は人が承認／**完全仲介**（許可の判断をLLMに任せず、ツールまたは独立したポリシー判定点で全リクエストを検証。可逆・軽微な操作は自動承認、不可逆・重大な操作は人の審査という段階的な運用）
- 被害を限定する対策：ツールと下流システムの操作ログ監視／呼出回数や累計金額に基づく閾値とサーキットブレーカー

**関連**：ASI01, ASI02, ASI03, ASI05, ASI07, ASI08, ASI09／AI 600-1：情報セキュリティ（主）、人間とAIの構成

## LLM04　サプライチェーン

**定義**：学習データ、モデル、アダプタ、変換パイプライン、実行基盤の完全性に影響する脆弱性。従来のソフトウェアの依存関係に加え、事前学習モデル・データセット・モデル成果物が改ざん・汚染・すり替えの対象になる。エージェント固有のサプライチェーン（MCPサーバ、ツールレジストリ）は ASI04 が扱う。

**典型例**：古い・脆弱な部品やモデル（コーディング支援が実在しないパッケージ名を提案し、攻撃者が先回りして登録する「スロップスクワッティング」を含む）／ライセンスの不整合／バックドア入りの事前学習モデル（安全とされる形式でも計算グラフに仕込める）／署名・ハッシュ固定のないモデル成果物のすり替え（`latest` のような可変参照で取得する場合に顕著）／LoRAアダプタや変換・統合・量子化工程の悪用／デバイス搭載モデルの改ざん／利用規約・プライバシーポリシーが不明確で入力データが学習に使われる。

**主要な対策**：データ・提供者の審査と利用規約の確認、変更時の再評価／脆弱性スキャンとパッチ方針（AIが提案した依存パッケージが実在し意図したものかを確認）／第三者モデル選定時のレッドチーミングと本番での異常検知／**SBOM を AIBOM・ML-BOM に拡張**した署名付き部品台帳（ライセンスも管理）／検証可能な出所のモデルのみ使用し、署名・ハッシュ・不変参照・リリースゲートを組み合わせる（**署名は完全性と出所を示すが安全性は示さない**）／共同開発環境の監視と、モデルの変換・統合サービスを高リスクの昇格点として扱う。

**関連**：ASI04／AI 600-1：バリューチェーンと構成要素の統合（主）、情報セキュリティ（主）／AI RMF：GOVERN 6・MAP 4・MANAGE 3（主）

## LLM05　データ・モデルのポイズニング

**定義**：データやモデル成果物を操作して、有害な振る舞い・偏り・悪用可能な弱点を埋め込む攻撃や不備。事前学習、ファインチューニング、埋め込み作成、RAG、モデル配布など、データを取り込み・変換・再利用するあらゆる段階で起きる。コードの修正で直せる通常の脆弱性と異なり、**データの再検証・再学習・モデルの交換が必要になり、復旧コストが大きい**。

**典型例**：学習データへの悪意あるデータ混入（拒否動作だけを弱め、通常の精度は保つ巧妙な手口を含む）／公開データセットへの混入が多数の下流モデルに波及／わずか250文書で6億〜130億パラメータのモデルにバックドアを仕込めたという研究／Webコンテンツ経由のメモリ・推薦の汚染／RAGナレッジベースの汚染／チャットテンプレートやトークナイザ設定への条件付き指示の埋め込み。

**主要な対策**：ML-BOM による系譜管理と署名検証／取り込みデータの厳格な検証と提供者審査／RAGの信頼境界・検索結果のフィルタ・出所スコアリング／サンドボックスでの隔離／学習損失・出力・挙動の異常検知／ドメイン特化の精選データでのファインチューニング／データのバージョン管理（ロールバックと調査のため）／自動再学習・フィードバックループへの人の監督と速度制限／トリガーを狙ったレッドチーミング（**安全性の調整でバックドアは除去されない前提**）／チャットテンプレート・トークナイザ設定・アダプタ・量子化成果物をコードと同様に扱い、署名・差分確認・静的解析を行う。

**関連**：ASI04, ASI06, ASI08／AI 600-1：情報の完全性・バリューチェーン・情報セキュリティ（いずれも主）

## LLM06　無制限のリソース消費

**定義**：推論の過剰・無制御な実行を許し、サービス停止、持続不能なコスト発生、モデル複製による知的財産の窃取を招く脆弱性。特徴は**コストの非対称性**で、攻撃者はわずかな負担で高額な計算を引き起こせる。推論（拡張思考）モデル、マルチモーダル、MCP等のツール連携で1件のリクエストが多数の処理に増幅されるため、**リクエスト数ベースのレート制限だけでは不十分**とされる。

**典型例**：可変長入力の大量投入と出力の暴走／ウォレット枯渇攻撃（Denial of Wallet）／コンテキスト上限ぎりぎりの要求の繰り返し／推論ループによる思考トークンの枯渇／計算量を最大化するよう最適化された入力／画像・音声の大量トークン化／API経由のモデル抽出・蒸留／ツール呼出の再帰・ファンアウト／推論基盤（vLLM、Ollama等）の脆弱性の悪用／長時間のエージェントセッションでコンテキストが膨らみ続ける（個々の要求は上限内でも総額が大きくなる）。

**主要な対策**：トークン数・推定コストに基づく上限と事前見積もりによる拒否／**API キー・ユーザー・チーム・クラウドアカウント単位の上書き不能な支出上限**（警告でなく停止）／動的なリソース配分／ネットワーク到達範囲の制限／高負荷時の段階的な縮退／キュー投入数の制限／敵対的な摂動の検査／ツール呼出の基準値監視／**エージェントのサーキットブレーカー**（ステップ数・再帰深度・実行時間・実行ごとのコスト上限。状態ハッシュでループ検知）／推論基盤の更新と認証の強制。

**関連**：ASI02, ASI08／AI 600-1：情報セキュリティ（主）、知的財産

## LLM07　誤情報

**定義**：LLMが、誤った・不完全な・根拠のない・誤解を招く情報を、人の判断や自動処理、エージェントの行動に影響するほどもっともらしく生成すること。**核心は誤った出力が信頼され、それに基づいて行動されること**にある。ハルシネーション、古い・不完全な文脈、根拠付けの弱さ、曖昧なプロンプト、検証されないツール出力などから生じ、攻撃者が意図的に引き起こすこともある。

**典型例**：根拠のない情報が業務・法務・医療・財務の判断に使われる／ワークフローで条件が満たされたと誤って推論し処理が進む／誤ったコードや実在しないパッケージの提案／要約で重要な制約・例外・期限が抜け落ちる／エージェント間で誤りが伝播する／捏造された証拠やタスク完了報告。

**主要な対策**：行動の前に権威ある最新の情報源で根拠付け／**生成と実行を分離し、主張を検証してから行動する（Claim-Check-Act）**／ツール呼出の引数・認可・前提条件・現在の状態を実行前に確認／確信度ではなく根拠性・一貫性のチェックを使う／重大な操作は承認ワークフロー／必須項目付きの構造化出力で抜け漏れを防ぐ／最小権限・サンドボックス・速度制限で被害範囲を限定／主張・証拠・結果のログと敵対的シナリオのテスト／検証済みの事実と推測を区別して提示し、人とシステムの信頼を較正する。

**関連**：ASI08, ASI09, ASI10／AI 600-1：情報の完全性・作話・人間とAIの構成（いずれも主）／AI RMF：MEASURE 2（主）

## LLM08　隠されたコンテキストの露出

**定義**：モデルのコンテキストに置かれた、ユーザーに見せない指示や運用情報（システムプロンプト、開発者指示、検索された方針文書、ツール・関数のスキーマなど）が抽出・推測・再構成されること。2025年版の「システムプロンプト漏洩」を拡張した項目である。

**設計の前提**：**隠されたコンテキストは見つかるものとして設計し、その中身を秘密とみなさない**。資格情報や接続文字列を入れない。認可・権限分離・ポリシー適用・コンテンツフィルタの境界として隠されたコンテキストに依存しない。

**深刻度の目安**

| 深刻度 | 隠されたコンテキストの中身・依存のしかた |
|---|---|
| 情報 | 秘密もセキュリティ上のロジックも含まず、機密性に依存していない |
| 中 | 内部ルール、フィルタ条件、役割記述、ワークフローのロジック（攻撃の助けになるが重要判断は左右しない） |
| 高 | 資格情報・トークンを含む、または認可・コンテンツ方針を機密性に依存している |
| 重大 | 露出がリモートコード実行、大規模なデータ持ち出し、権限昇格につながる |

**主要な対策**：機密データを隠されたコンテキストに置かず、モデルが直接触れないシステムに外出しする／重要な振る舞いはモデル外の決定論的なガードレールで制御する／**認可とアクセス制御を LLM から独立させる**（決定論的・監査可能な方法で）。

**関連**：ASI06, ASI07／AI 600-1：情報セキュリティ（主）

---

## LLM09　ベクトル・埋め込みの弱点

**定義**：テキストや画像を数値ベクトルに変換し、類似検索でモデルに見せる内容を決めるすべての仕組み（RAG、ベクトル型のエージェントメモリ、セマンティックキャッシュ、重複排除）に生じるリスク。類似検索がデータ源とプロンプトの間にある限り、**埋め込み層はアプリの信頼境界の一部**になる。

**整理の視点**：ポイズニングはシステムを「誤らせ」、逆変換は「漏らし」、ジャミングは「黙らせ」、アクセス制御の失敗は「見境をなくす」。

**典型例**：共有インデックスで類似検索が全データに走った後にアプリ側で権限フィルタをかけるため、件数・スコア・応答時間から他テナントの文書の存在を推測される／**保存された埋め込みから原文を復元する逆変換**（埋め込みだけの漏洩も原文漏洩と同等に扱う必要がある）／検索時のデータ汚染／回答を拒否させる「妨害文書」によるジャミング／類似度スコアを返すことによる所属推論／セマンティックキャッシュ・重複排除の汚染／画像などマルチモーダル埋め込みの汚染。

**主要な対策**：テナント範囲をインデックス照会の中で適用しサーバ側で検証（クライアントが指定する範囲は制御ではない）、高機密はインデックスを物理分離、チャンク単位のアクセス制御／埋め込み前の正規化（ゼロ幅文字・白文字・同形異字の除去）、埋め込みごとの出所記録、埋め込みモデル自体の審査／信頼度の異なるデータを同じインデックスに混在させない／取り込み時・検索時の異常検知、生の類似度スコアを返さない／元文書削除時の埋め込み削除、ベクトルDBのバックアップを元文書と同じ機密区分で管理、埋め込みAPIキーを秘密情報として扱う／**インシデント対応手順で「埋め込みのみの漏洩」を原データ漏洩として扱う**。

**関連**：ASI04, ASI06／AI 600-1：データプライバシー・情報セキュリティ・情報の完全性（いずれも主）

## LLM10　不適切な出力処理

**定義**：LLMの出力を、下流のコンポーネントやシステムに渡す前の検証・無害化・処理が不十分であること。LLMの出力はプロンプトで操作できるため、ユーザーに追加機能への間接的なアクセスを与えるのと同じである。ブラウザでの XSS・CSRF、バックエンドでの SSRF・権限昇格・リモートコード実行につながる。2026年版では、アシスタントが大量に生成する安全でないコードも範囲に含めた。

**典型例**：出力をシェルや `exec`／`eval` に直接渡す／生成された JavaScript・Markdown がブラウザで解釈される／生成SQLをパラメータ化せず実行／出力からファイルパスを組み立てる（パストラバーサル）／メールテンプレートへの未エスケープ挿入／ANSIエスケープ等の制御文字が端末・ログ・IDEで解釈される／**チャットUIが出力中の Markdown 画像やリンクプレビューを自動取得し、URL経由で会話データが持ち出される**／生成コードをレビューなしにビルド・デプロイする。

**主要な対策**：モデルを他のユーザーと同様にゼロトラストで扱い、出力を入力として検証／OWASP ASVS に沿った検証と無害化／出力先に応じたエンコード（HTML、JavaScript 等）／パラメータ化クエリ／厳格な CSP／出力の異常パターン監視／制御文字の除去／**クライアント側で Markdown 画像・リンクプレビュー・iframe の自動描画を既定で無効化**し、必要な場合は許可リストかサーバ側プロキシ経由に限定。

**関連**：ASI02, ASI05, ASI09／AI 600-1：情報セキュリティ（主）

---

## この章の結論

- 10リスクに共通する設計原則は、**「信頼境界・権限・承認・検証をモデルの外で決定論的に実装する」**ことである。
- 優先順位は2026年版の順位をそのまま使ってよいが、エージェント型では LLM03 と LLM01 の組合せを、RAG型では LLM02 と LLM09 の組合せを最初に審査する（第7章）。
