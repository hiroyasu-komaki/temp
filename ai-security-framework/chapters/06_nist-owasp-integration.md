# 第6章　NIST × OWASP の統合

> **この章の位置づけ**：ガバナンス層（NIST）と技術対策層（OWASP）を、公式の対応表に基づいて接続する
> **対象読者**：セキュリティガバナンス担当、CISO、監査対応担当

## 要旨

- 二層の役割は明確に分ける：NIST は「何を、誰が、どの水準で管理するか」、OWASP は「何を防ぎ、どう実装・検証するか」。
- 接続には独自の対応表を作らず、**OWASP が公式に提供する対応表**を使う：①LLM Top 10 2026 付録A（AI 600-1・AI RMF との対応、版固定）、②OWASP GenAI Security Crosswalk（CSF 2.0 を含む26枠組みとの対応）。
- 公式対応表から分かる重要な事実：**OWASP の10リスクは AI 600-1 とは強く対応するが、AI RMF とは大半が「補助的」な対応にとどまる**。AI RMF は成果目標の枠組みで、技術的な脅威を直接は記述しないためである。この隙間を埋めることが二層構造の存在理由である。

## 6.1 二層の役割分担

| 観点 | ガバナンス層（NIST CSF 2.0 ＋ AI RMF ＋ AI 600-1） | 技術対策層（OWASP LLM／Agentic Top 10） |
|---|---|---|
| 問い | どのAIを使ってよいか、誰が承認し、どう監督するか | このシステムで何が起きうるか、何で防ぎ、どう確かめたか |
| 粒度 | 組織の方針・プロセス・体制 | アーキテクチャ・実装・テスト |
| 主な担い手 | セキュリティガバナンス、法務、AI推進、経営層 | 案件担当、アーキテクト、開発・運用 |
| 成果物 | AI利用方針、AIシステムの棚卸し（台帳）、審査プロセス、残留リスクの記録、経営・監査への報告 | チェックシート、脅威モデル、レッドチーミング結果、ガードレール設定、監視ルール |
| 更新頻度 | 年次・改訂時 | 案件ごと・リリースごと |

## 6.2 AI RMF の4機能に OWASP の活動をどう入れるか

| AI RMF 機能 | 根拠となるサブカテゴリ | 技術対策層の活動（OWASP 由来） |
|---|---|---|
| **GOVERN** | 1.3 リスク許容度に応じた活動レベル／1.6 棚卸し／6.1 サードパーティ | 生成AI利用方針（入力禁止データ、承認が必要な操作の定義）、AI資産台帳（モデル・プロンプト・ツール・MCPサーバ・データソース・入力チャネル）、提供者審査と利用規約の確認（LLM04） |
| **MAP** | 2.2 知識の限界と人間によるオーバーサイト／3.5 ヒューマンオーバーサイト／4.1・4.2 構成要素のリスク | 脅威モデリング（注入の経路・伝播・符号化の3軸で分解、LLM01）、Rule of Two による構成評価、RAGの権限境界とデータ分類の特定（LLM02/09）、承認ポイントの設計（LLM03） |
| **MEASURE** | 1.3 独立評価者／2.4 実稼働時のモニタリング／2.7 セキュリティとレジリエンス | 適応型攻撃者を想定したレッドチーミング（LLM01）、漏洩レッドチーミング（LLM02）、トリガー探索（LLM05）、根拠性・一貫性の評価（LLM07）、出力の無害化テスト（LLM10） |
| **MANAGE** | 1.3 対応の選択肢／1.4 残留リスク／2.4 停止の仕組み／3.2 事前学習済みモデルのモニター／4.3 インシデント通知 | 入出力ガードレール、検索前の認可、支出上限・サーキットブレーカー（LLM06）、キルスイッチ、「埋め込みのみの漏洩」を原データ漏洩として扱うインシデント手順（LLM09） |

**読み取れること**

- AI 600-1 の「情報セキュリティ」は10リスクすべてにかかわり、9件で主要な対応である。AI 600-1 の推奨行動のうち「情報セキュリティ」が付記されたものが、技術対策層と最も直接につながる。
- 誤情報（LLM07）は情報セキュリティよりも「情報の完全性・作話・人間とAIの構成」と強く結びつく。**セキュリティ部門だけでなく、業務部門の利用ルール（検証してから使う）とセットで管理する**必要がある。
- 第2章で範囲外とした AI 600-1 のリスク（CBRN、環境、バイアス、わいせつ）は、OWASP の10リスクとはほぼ対応しない。範囲設定の妥当性を裏づけている。

## 6.4 公式対応表②：OWASP LLM Top 10 2026 × NIST AI RMF

出典：同 Appendix A（AI RMF 1.0 に版固定、カテゴリ単位）。●＝ほぼそのまま当てはまる、○＝部分的・ガバナンス水準での対応。

| リスク | 対応する AI RMF カテゴリ |
|---|---|
| LLM01 プロンプトインジェクション | ○ MEASURE 1（静的でなく適応型攻撃の指標）／○ MEASURE 2（防御仕様を開示したレッドチーミング）／○ MAP 4（構成要素ごとの脅威モデリング） |
| LLM02 機密情報の漏洩 | ○ MAP 5（データ主体へのインパクト）／○ MEASURE 2（漏洩レッドチーミングをリリース判定に）／○ MANAGE 4（漏洩時の通知・対応・復旧） |
| LLM03 過剰な権限 | ○ MANAGE 4（ツール操作の監視とサーキットブレーカー） |
| **LLM04 サプライチェーン** | **● GOVERN 6（サードパーティ方針）／● MAP 4（全構成要素のリスク）／● MANAGE 3（サードパーティのリスク管理）**／○ MEASURE 2／○ MEASURE 3 |
| LLM05 データ・モデルのポイズニング | ○ MEASURE 3（ドリフトの追跡）／○ MEASURE 2（トリガー探索）／○ GOVERN 6（データ提供者の管理） |
| LLM06 無制限のリソース消費 | ○ MANAGE 1（支出上限・サーキットブレーカーによる優先対応）／○ MEASURE 2 |
| **LLM07 誤情報** | **● MEASURE 2（妥当性・信頼性の評価）**／○ MEASURE 1／○ MEASURE 3／○ MANAGE 1 |
| LLM08 隠されたコンテキストの露出 | ○ MEASURE 2（コンテキスト抽出のレッドチーミング） |
| LLM09 ベクトル・埋め込みの弱点 | ○ MAP 4（埋め込み層を信頼境界に含める）／○ MAP 5／○ MANAGE 4 |
| LLM10 不適切な出力処理 | 対応なし |

**読み取れること**

- AI RMF と「ほぼそのまま」対応するのは **LLM04（サプライチェーン）と LLM07（誤情報）だけ**である。それ以外は部分的な対応にとどまり、LLM10 は対応がない。
- つまり **AI RMF だけを導入しても、プロンプトインジェクションや出力処理の技術対策は担保されない**。AI RMF は「評価せよ（MEASURE 2）」「対応せよ（MANAGE）」とは言うが、何をどう評価・対応するかは言わない。そこを OWASP で埋めるのが本資料の二層構造である。
- 逆に、OWASP だけでは「誰が承認し、残留リスクを誰が受容するか」（GOVERN 2、MANAGE 1.4）が決まらない。

> 注：OWASP GenAI Security Crosswalk にも AI RMF とのサブカテゴリ単位の対応表があるが、付録Aと対応が一致しない箇所があり、Crosswalk は名前のある査読者が承認するまで行を「未レビュー」と扱っている。本資料では、版が固定され Top 10 本体の一部である付録Aを一次根拠とする。

## 6.6 Crosswalk の使い方

| 用途 | 機能 | 当社での使い方 |
|---|---|---|
| 準拠状況の把握 | Score（実装している枠組みを選ぶとギャップを表示） | 年次で CSF 2.0・ISO/IEC 27001 等の実装状況からギャップを確認し、第9章のロードマップに反映 |
| 個別リスクの管理策検索 | Explorer、各枠組みの Markdown | 案件レビューで「このリスクにはどの既存管理策が効くか」を引く |
| 監査・報告 | `compliance-report`（OSCAL 形式での出力に対応） | GRC ツールへの取り込み、経営・監査向けの報告 |
| 事例の参照 | Incidents | 審査やトレーニングでの具体例 |

## 6.7 その他の関連枠組み

当社はグローバルに事業を行うため、NIST・OWASP 以外の枠組みとも整合を取る必要がある。いずれも Crosswalk の対応先に含まれる（AI事業者ガイドラインを除く）。

| 枠組み | 位置づけ | 本資料との関係 |
|---|---|---|
| ISO/IEC 42001:2023 | AIマネジメントシステムの国際規格（認証可能） | AI RMF の GOVERN と重なる。認証を目指す場合のマネジメントシステム側の枠組み |
| ISO/IEC 27001:2022 | 情報セキュリティマネジメントシステム | 既存のISMSに生成AIの管理策を追加する場合の受け皿 |
| EU AI Act（Regulation (EU) 2024/1689） | EUの法規制。リスク区分に応じた義務 | 欧州拠点・欧州向けの利用で適用。高リスク区分の義務の適用時期は最新状況を確認する |
| AI事業者ガイドライン 第1.2版（2026-03-31、総務省・経済産業省） | 日本の事業者向けガイドライン。AI推進法（2025年9月全面施行）に基づく指針の下に位置づけられる | 国内の説明責任の基準。第1.2版でAIエージェントを定義 |
| CSA AI Controls Matrix（AICM）v1.1 | クラウド・AIの管理策マトリクス | クラウド事業者・SaaS の評価に使う。Top 10 付録Aにも対応表がある |
| MITRE ATLAS | AIシステムへの攻撃の戦術・技術の知識ベース | レッドチーミングのシナリオ設計、脅威インテリジェンス |

## この章の結論

- NIST と OWASP の接続には、OWASP 公式の対応表（Top 10 付録A、Crosswalk）を使い、独自の対応表は作らない。
- AI RMF だけでは技術対策が担保されず、OWASP だけでは責任と受容の判断が決まらない。二層を組み合わせて初めて閉じる。
- 既存の CSF 運用では、まず **DE.CM-01（監視）、PR.DS（データ保護）、PR.AA（権限）、GV.SC（サプライチェーン）、ID.AM-08（資産台帳）** の運用範囲に生成AIを含める。
