## 1. 業務用語

業務の流れの順に並べる。

| 用語 | 読み | 定義 | 定義の出典 | 備考 |
|---|---|---|---|---|
| 移管 | いかん | 移管元のファンクションのシステムに関する経費予算と、それに伴う間接業務を、GDS へ移すこと | [憲章](../rules/02-charter.docx) 第3条、第4条 | 直接業務は移らない。設備投資の予算は対象にしない |
| 移管元 | いかんもと | 予算を GDS に移すファンクション。営業部門以外で、本社機能のうち人事・総務・財務を含む | [憲章](../rules/02-charter.docx) 第4条 | 移管元には案内済み |
| カウンターパート | カウンターパート | 移管元で、担当BP と予算移管のやりとりをする担当者 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.5 | |
| 経費予算 | けいひよさん | 保守・ライセンス・運用・利用料など、システムを使い続けるための予算 | [憲章](../rules/02-charter.docx) 第8条 | 移管する |
| 設備投資の予算 | せつびとうしのよさん | 新規導入・改修など、固定資産の取得につながる予算 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.8、[憲章](../rules/02-charter.docx) 第8条第3項 | 予算移管の対象にしない。移管の後に着手する IT投資は GDS が管理する（新しいITガバナンスモデル） |
| 予算区分 | よさんくぶん | 案件が経費予算か投資予算（設備投資）かの区分 | [憲章](../rules/02-charter.docx) 第8条 | 混在する案件は行を分ける |
| システム関連 | システムかんれん | 案件がシステムの利用・保守・開発・運用に関わるかどうかの区分 | [憲章](../rules/02-charter.docx) 第8条 | |
| 間接業務 | かんせつぎょうむ | 移管した予算に伴う業務。予算管理・契約管理・発注・支払 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.5、[憲章](../rules/02-charter.docx) 第4条第3項 | 移管の後は GDS が責任を持って管理・実行する |
| 直接業務 | ちょくせつぎょうむ | 各ファンクションの組織のミッション・業務分掌・職務権限に基づく本来の業務 | [憲章](../rules/02-charter.docx) 第4条第3項 | 移管しない。例えば営業部門の予算を移管しても、GDS は営業活動をしない |
| ヒアリングシート | ヒアリングシート | 担当BP が移管元と、移管する予算、紐づく契約、移管の後に引き継ぐ業務と時期を確かめるためのシート | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.5 | 記録は、各ファンクションと GDS の双方が編集できる既存の SharePoint フォルダに置く |
| 予算シート | よさんシート | S&G が提示する、移管元の予算に移管判定とステータスの列を足した案件の一覧。予算移管シート（budget_transfer_sheet.xlsx）の「予算一覧」シート | [憲章](../rules/02-charter.docx) 第6条 | 対象外の行は除外し（ステータス「対象外」）、追加分は追記する |
| 案件 | あんけん | 予算シートの1行 | [憲章](../rules/02-charter.docx) 第8条 | |
| 移管判定 | いかんはんてい | 予算シートの数式が出す、案件の扱い（移管・対象外・判定保留） | [憲章](../rules/02-charter.docx) 第8条 | 手で上書きしない |
| ステータス | ステータス | 案件ごとの進み具合。未着手・確認中・合意済み・引継ぎ開始・要協議・対象外の6つ | [憲章](../rules/02-charter.docx) 第10条 | 担当BP が随時更新し、S&G が随時確認する |
| 完了目処 | かんりょうめど | 担当BP が11月末に S&G へ報告する、12月第1週に作業を終えられるかどうかの見込み | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.5 | 間に合わない案件は「要協議」とし、S&G と協議する |
| 完了の定義 | かんりょうのていぎ | 12月末の時点で、担当BP（経費予算・固定資産）と S&G がそれぞれ満たしている状態 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.5、[憲章](../rules/02-charter.docx) 第3条第2項 | 契約の名義変更・請求書の宛名の変更・引き継ぎの完了は含まない |
| 移管の稟議 | いかんのりんぎ | 移管する予算を、移管元と GDS の部門長の合意を前提に、稟議システムで GDS へ移す手続き。S&G が申請単位ごとに準備・申請する | [憲章](../rules/02-charter.docx) 第9条第2項 | 2026-12-31 までに完了させる。承認の目安は12月第3週の前半 |
| 一括移管 | いっかついかん | 移管するものを、一括移管の実施日（2027-01-01）にまとめて移すこと | [憲章](../rules/02-charter.docx) 第9条 | |
| 既存資産 | きぞんしさん | 移管の時点で償却中の資産（簿価ゼロを含む）と、SaaS 導入などの長期前払費用 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.8、[憲章](../rules/02-charter.docx) 第12条 | 移さない。固定資産管理と減価償却費は移管元のまま |
| 取得予定 | しゅとくよてい | 移管の時点で構築中で、移管の後に本勘定へ振り替える資産 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.8 | 仮勘定は移管元。振替の時点から固定資産管理と減価償却費は GDS |
| 将来取得 | しょうらいしゅとく | 移管の後に着手する IT投資で取得する資産 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.8 | 仮勘定の時点から GDS が管理する |
| 既存資産の改修 | きぞんしさんのかいしゅう | 移管の後に、既存資産を改修するもの | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.8、[憲章](../rules/02-charter.docx) 第12条第4項 | 改修分は GDS が持ち、本体は移管元に残す（追補の推奨） |
| ビジネス領域 | ビジネスりょういき | 移管の後に各ファンクションが R・A を持つ領域。ビジネス戦略・ビジネス要件・ビジネス効果（何を・なぜ実現するか） | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.6、[憲章](../rules/02-charter.docx) 第11条 | |
| IT主導の領域 | アイティーしゅどうのりょういき | 移管の後に GDS が R・A を持ち、各ファンクションが C を持つ領域。IT戦略・システム要件・ソリューション・ベンダー（どう実現するか） | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.6、[憲章](../rules/02-charter.docx) 第11条 | 全社共通と個別最適のバランスは GDS がとる |
| 部門に閉じた案件 | ぶもんにとじたあんけん | 他システムとのデータ連携、ファンクションの外の利用者、GxP・個人情報のいずれにも当てはまらない案件 | [追補「IT予算移管の要点」](../kickoff/IT予算移管の要点_予算ガイドライン追補.pptx) p.6・p.7 | IT主導の領域のうちシステム要件までを各ファンクションがリードしてよい。ソリューション選定とベンダー選定はどの案件でも GDS がリードする。判定は受付の時点で GDS が行う |

## 4. 使い分け

| 区別すべき語 | 使い分け |
|---|---|
| 「S&G」と「担当BP」 | S&G＝全体の把握、移管対象の報告、稟議、固定資産の扱いの確認。担当BP＝案件ごとの特定・合意、予算シートの更新、引き継ぎ、固定資産の案件の特定 |
| 「S&G」と「FinanceBP」 | 予算移管の文脈では同じ意味で使う |
| 「予算の承認」と「予算の移管」 | 予算の承認＝取締役会が会社全体の予算を承認すること（移管する予算も移管元の予算として計上する）。予算の移管＝承認の後、部門長同士の合意を前提に稟議で GDS へ移すこと |
| 「移管判定」と「ステータス」 | 移管判定＝移すかどうか（数式で自動）。ステータス＝どこまで進んだか（担当BP が更新） |
| 「直接業務」と「間接業務」 | 直接業務＝各ファンクションの本来の業務（移管しない）。間接業務＝移管した予算に伴う予算管理・契約管理・発注・支払（GDS が担う） |
| 「ビジネス領域」と「IT主導の領域」 | ビジネス領域＝何を・なぜ実現するか（各ファンクションが R・A）。IT主導の領域＝どう実現するか（GDS が R・A、各ファンクションが C） |
| 「取得予定」と「将来取得」 | 取得予定＝移管の時点で構築中（仮勘定は移管元、振替の時点から GDS）。将来取得＝移管の後に着手（仮勘定から GDS） |
| 「移管する」と「決裁権を持つ」 | 移管する＝予算と間接業務の所在を GDS に移す。決裁権を持つ＝案件の実行を承認する。決裁権は新しいITガバナンスモデル（Tier）が決める |

| IT部門 | GDS | 社内の呼称に合わせた |
| ビジネス部門、移管対象部門 | 各ファンクション、移管元 | |

| 窓口担当（旧: 案件担当） | 担当BP | |
| IT部門長 | GDS部門長 | |
| 移管対象部門の担当者 | カウンターパート | |
| 移管ステータス（棚卸し中・棚卸し済み・合意済み・準備完了・対象外） | ステータス（未着手・確認中・合意済み・引継ぎ開始・要協議・対象外） | 12月末の完了の定義に合わせた |

| 進行役・案件担当、キックオフ | S&G・担当BP、活動の開始（追補の公開） | |
