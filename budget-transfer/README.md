# IT予算移管

2027年度の予算編成から、移管対象部門（営業部門以外の部門）のシステムに関する予算・契約と、契約に基づく間接業務（予算・契約の管理、発注・検収・支払い、委託先の管理など）を、IT部門へ移管するプロジェクト。各部門の本来の業務（直接業務）は、組織のミッション・業務分掌・職務権限に基づき、従前どおり各部門が担う（[憲章](./rules/02-charter.docx) 第4条第3項）。

- **方針**：移管できるものは全て移管し、全ての案件の予算を一括して移す（今年度から続く投資案件は部門に残す）。個別移管と案件の保留はしない。今の担当が SOP・規程など承認済みの文書で定められ、担当の変更に正式な手続き（例：GxP の変更管理）が要る業務だけ、手続きが完了するまで今の担当のまま行う（経過措置）。移管の時点では契約について手続きを行わない（次回の更新から署名者が IT部門に変わる。請求書の宛名の変更は、ベンダーマネジメント担当が2月初旬までに連絡する）（[憲章](./rules/02-charter.docx) 第9条・第11条）。
- **移管の後の役割分担**：直接業務は部門に残り、間接業務は IT部門に移る。その間の IT関連業務（中間層）は、標準 RACI を案件ごとにカスタマイズした合意文書で扱いを決める。業務の最終責任（A）はビジネスオーナーに残る（[憲章](./rules/02-charter.docx) 第4条第5項、[APX-01](./appendix/01-post-transfer-operating-model.md)）。
- **予算の流れ**：移管対象部門は移管する予算も含めて2027年度予算に計上し、取締役会の承認を受ける。その後、部門長同士の合意による稟議（移管の稟議）で、2026-12-31までに IT部門へ移す（[憲章](./rules/02-charter.docx) 第9条）。
- **12月末のゴール**：移管の稟議が承認されていること。その前提として、(1) 稟議に必要な情報が整理されている、(2) 12月末の時点で完了していないこと（SOPの改訂、契約の署名者の変更、請求書の宛名の変更など）が明確になっている、(3) 2027年1月から契約の管理と請求書の支払いなどの間接業務を IT部門が始められる、の3つがそろっていればよい（[憲章](./rules/02-charter.docx) 第3条第2項、[Runbook 全体編](./process/08-runbook-00-overview.md) §1.3）。
- **進め方**：引継ぎ要領をキックオフの前（2026-10-30）までに確定させることを、予算移管の開始条件とする。2026-10-01〜10-31 にヒアリング（IT部門内の事前の情報整理）を行い、2026-11-02 のキックオフ（IT部門内。案件担当向け）の後、11月に部門の担当者の確認を得る。合意文書の承認（合意の期限）は 2026-12-11、準備完了の確認は 2026-12-18 までに行う。この間、案件担当が予算一覧の移管ステータスを随時更新し、進行役が毎日確認する。部門の案件の移管ステータスが埋まった時点で、移管の稟議を起票する。
- **体制**：実務は予算移管担当の二者が行う。全体を進める進行役（1名）と、案件ごとの案件担当（普段からその案件でビジネス部門のカウンターパートを務めている IT部門のメンバー）である。移管元の責任者と IT部門長は承認だけを行う。ベンダーマネジメント担当・事務担当は、移管の後に間接業務を担う受け手である（[憲章](./rules/02-charter.docx) 第5条・第6条・第11条）。

- 文書一式は作成を終えた。全文書は承認前の案で、IT部門長の承認を待っている。
- 主な決定（決定記録「決定事項」54件）：
