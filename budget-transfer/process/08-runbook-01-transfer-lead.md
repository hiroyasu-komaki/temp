## 1. 概要

### 1.1 目的

予算移管の実務は、全体を進める **進行役**（1名）と、案件ごとの **案件担当**（複数）の二者で行う（[憲章](../rules/02-charter.docx) 第5条・第6条）。この文書は進行役の手順を定める。案件担当の手順は [Runbook 案件担当編](./08-runbook-04-case-owner.md) に定める。

進行役は、キックオフ、予算シートの登録と案件担当の割当て、引継ぎ要領の整備、移管の稟議の起票、移管ステータスと進捗の確認、進捗のまとめを行い、IT部門長への承認・決定の依頼を一本化する。

承認者（移管元の責任者、IT部門長）は承認だけを行い、実務は行わない。移管するのは予算・契約と、契約に基づく間接業務であり、移管対象部門の直接業務は扱わない（憲章 第4条第3項）。移管の後に間接業務を担うベンダーマネジメント担当（契約）と事務担当（請求書の支払いなどの事務手続き）は、受け手として相談を受ける（憲章 第11条）。

### 1.2 対象範囲

| 対象 | 対象外 |
|---|---|
| 移管対象部門の2027年度予算のうち、システムに関する予算・契約と、契約に基づく間接業務（憲章 第4条） | 移管対象部門の直接業務（憲章 第4条第3項）、継続している投資案件（憲章 第8条第3項）、移管対象外の部門の予算、システムと関係のない予算・契約・業務、移管したものの決裁権、移管した費用の配賦（憲章 第4条）、移管の後の契約の精査と請求書の支払い（憲章 第11条） |

### 1.3 関係者

| 関係者 | 進行役との関わり | 連絡先 |
|---|---|---|
| 案件担当 | 案件の割当てを伝える／案件の状況・合意文書・例外を受け取る／稟議の結果を伝える | 予算移管シート「予算一覧」の案件担当 |
| 移管対象部門の担当者 | 予算シートを受け取る | 予算移管シート「窓口」に記録した担当者 |
| 移管元の責任者（部門長） | 移管の稟議の承認を求める（予算移管の案内は済んでいる） | 予算移管シート「窓口」に記録した責任者 |
| IT部門長 | 移管の稟議の承認、確認依頼・保留課題の決定を求める／進捗のまとめを送る | — |
| ベンダーマネジメント担当・事務担当（移管の後の受け手） | 引継ぎ要領を相談する | — |

### 1.5 承認の依頼

承認者は実務を行わないため、承認の依頼と、承認の結果の記録（決定記録、予算移管シート「進捗」）は進行役か案件担当が行う。IT部門長への依頼と稟議は進行役に一本化する。移管元の責任者への案件ごとの承認（A-03）は案件担当が依頼する（[案件担当編](./08-runbook-04-case-owner.md) §1.5）。

| 進捗の行 | 承認者 | 承認すること | 依頼する者 | 依頼する手順 | 承認の後に起きること |
|---|---|---|---|---|---|
| A-03 | 移管元の責任者 | 合意文書（間接業務の引継ぎの方法、IT関連業務の扱い、経過措置） | 案件担当 | 案件担当編 §3.4 | 合意を記録する（案件担当編 §3.5） |
| A-05 | 移管元の部門長・IT部門長（部門長同士の合意） | 移管の稟議（部門の一括移管分の予算） | 進行役 | §3.4 | 一括移管分の予算が IT部門に移る |
| A-08 | IT部門長 | 確認依頼と保留課題（[決定記録](../reference/15-decision-log.xlsx)） | 進行役 | 随時 | 回答・確定内容を各文書に反映する |

### 1.6 進捗の記録のしかた

1. 進行役は、次のタイミングで、予算移管シート「進捗」に行を作る（担当者・期限を入れる）。案件ごとの行は、案件担当が作る（案件担当編 §1.6）。

| タイミング | 作る行 |
|---|---|
| 予算シートの登録（§3.2。ヒアリングの開始の前） | 全体で P-01・P-03・P-06・P-07・A-08。部門ごとに P-02・P-04・A-05 |

2. 自分の行（P-01〜P-07）の「状態」（未着手／進行中／完了／保留）と「完了日」を更新する。保留にしたときは、メモに理由を書く。
3. 承認の行（A-05・A-08）は、承認を得たときに更新する。承認者は記入しない。
4. 毎日の確認（§3.6）で、期限超過と保留の行を確かめる。

## 3. 手順

**進捗の記録**: 予算移管シート「進捗」の自分の行（P-01〜P-07）と、承認の行（A-05・A-08）を更新する（§1.6）。

### 3.1 キックオフを開催する

| 項目 | 内容 |
|---|---|
| 開始条件 | 年間カレンダー「キックオフ」の日になった。引継ぎ要領が確定している（§3.3。予算移管の開始条件） |
| 入力 | [Runbook 全体編](./08-runbook-00-overview.md)・[案件担当編](./08-runbook-04-case-owner.md)、予算移管シート、[移管対象部門ガイド](../reference/12-handbook.pptx) |
| 担当 | 進行役（参加者は案件担当。IT部門内で行う） |
| 期限 | 年間カレンダー「キックオフ」 |
| 出力 | 案件担当への説明（進め方、12月末のゴール、引継ぎ要領） |

移管対象部門には予算移管を案内済みのため、キックオフに部門は招かない。部門への説明は、案件担当がヒアリングと確認のときに行う（案件担当編 §3.1）。

**作業**

1. 案件担当に、キックオフの開催を案内する。
2. 案件担当編と予算移管シートで、案件担当の手順・期限と、12月末のゴール（移管の稟議の承認。全体編 §1.3）を説明する。
3. 引継ぎ要領（案件担当編 付録）を説明する。
4. 移管対象部門への説明は、移管対象部門ガイドの範囲で行うことを確かめる。
5. キックオフで出た質問と回答を記録する。

**例外**: —

### 3.2 予算シートを登録し、案件担当を割り当てる

| 項目 | 内容 |
|---|---|
| 開始条件 | 移管対象部門の予算シートを受け取った（キックオフの前） |
| 入力 | 予算シート（今年度実績・来年度予算） |
| 担当 | 進行役 |
| 期限 | 年間カレンダー「ヒアリングの開始」の前日 |
| 出力 | 予算一覧の案件（案件ID、部門、予算区分、投資の区分、システム関連、案件担当） |

**作業**

1. 「窓口」に、部門名・責任者・担当者・連絡先・予算シートの受領日を記入する。
2. 予算シートの各行を予算一覧に転記し、案件IDを振る。
3. 投資予算と経費予算が混在する行を、2行に分ける（憲章 第8条第2項）。
4. 部門・予算区分・システム関連を記入する。投資予算の案件には、投資の区分（新規／継続。今年度から続く案件は継続）を記入する。予算シートから分からない項目は「未確認」にする。
5. 経費予算の案件に、費用の性質を記入する。
6. 案件ごとに、普段その案件でビジネス部門のカウンターパートを務めている IT部門のメンバーを、案件担当として記入する。カウンターパートがいない案件は、IT部門長に割当てを相談する。
7. 移管ステータスを「棚卸し中」にし、ステータス更新日を記入する。
8. 案件担当に、割り当てた案件を連絡する。
9. §1.6 の行を「進捗」に作る。

**例外**: 予算シートがない部門がある、カウンターパートが決まらない → §4

### 3.3 引継ぎ要領を整える

| 項目 | 内容 |
|---|---|
| 開始条件 | 予算シートの登録と案件担当の割当て（§3.2）が済んだ |
| 入力 | [案件担当編](./08-runbook-04-case-owner.md) 付録「引継ぎ要領」（案）、ベンダーマネジメント担当・事務担当の既存の手順 |
| 担当 | 進行役（ベンダーマネジメント担当・事務担当に相談する） |
| 期限 | 年間カレンダー「引継ぎ要領の確定の期限」（2026-10-30。キックオフの前） |
| 出力 | 確定した引継ぎ要領（案件担当編 付録） |

引継ぎ要領は、案件担当が移管対象部門から間接業務を受け取り、受け手（ベンダーマネジメント担当・事務担当）に渡すときの受け渡しの決まりである。キックオフまでに確定していることを、予算移管の開始条件とする。IT部門長の承認は要さない。移管の後の契約の精査や請求書の支払いの手順そのものは、受け手が定める。

**作業**

1. 付録の受け手の対応表（付録1）を、ベンダーマネジメント担当・事務担当に確かめる。
2. 受け取るもの（付録2）と受け手を、受け手と確かめて付録に書き込む（受け渡しの置き場所は周知済みのため書かない）。
3. 請求書の宛名の変更の連絡に必要な情報（付録2・付録3）を、ベンダーマネジメント担当と確かめる。
4. 確定した付録を案件担当に知らせる。案件の引継ぎで足りないことが分かったら、付録を改め、案件担当に知らせる。

**例外**: 期限までに確定しない → §4

### 3.4 移管の稟議を起票する

| 項目 | 内容 |
|---|---|
| 開始条件 | その部門の案件の移管ステータスが全て埋まった（「合意済み」「準備完了」「対象外」のどれかになった） |
| 入力 | 予算一覧（移管判定（予算）が移管の案件と、その来年度予算） |
| 担当 | 進行役 |
| 期限 | 年間カレンダー「移管の稟議の完了期限」（2026-12-31） |
| 出力 | 移管の稟議（部門ごとに1本）の承認 |

**作業**

1. 予算一覧で、その部門の移管判定（予算）が「移管」の案件を抽出する（経過措置がある案件も含め、全額を移す）。
2. 案件ごとに、来年度予算の年額を確かめる。
3. 抽出した案件の一覧と一括移管分の予算額をまとめ、稟議システムで移管の稟議を起票する。承認者は、移管元の部門長と IT部門長とする（部門長同士の合意）。
4. 稟議の承認を得たら、「進捗」の A-05 を更新し、案件担当に連絡する。

**例外**: 「移管の稟議の完了期限」までに合意済みにならない案件がある、稟議が承認されない → §4

### 3.5 （欠番）

個別移管分の稟議（旧 P-05）は廃止した。予算は、全ての案件で一括して移す。担当の変更に正式な手続きが要る業務は、予算を移したうえで、手続きが完了するまで今の担当のまま行う（経過措置。憲章 第9条第3項）。

### 3.6 移管ステータスと進捗を確認する

| 項目 | 内容 |
|---|---|
| 開始条件 | 毎日（案件担当が移管ステータスを随時更新するため） |
| 入力 | 予算一覧、「進捗」、案件担当から受け取った合意文書 |
| 担当 | 進行役 |
| 期限 | その日のうち |
| 出力 | 案件担当への確認の依頼、合意文書の横並びの確認の結果、期限超過・保留の確認の結果 |

**作業**

1. 予算一覧で、「確認（自動）」が空でない案件を抽出し、案件担当ごとに一覧にして、移管ステータスの見直しを依頼する（見直しのしかたは案件担当編 §3.10）。
2. 案件担当が空欄の案件を抽出し、割り当てる（§3.2 の手順6）。
3. 案件担当から受け取った合意文書を横並びで確かめる。標準 RACI から変えてよい範囲（IT関連業務の行の R・C と、SO が R を持ち始める時期。BTR-APX-01 §5.3）を外れていないか、経過措置の手続きと完了予定が書かれているかを見る。外れていれば案件担当に直しを依頼する。
4. 「進捗」で、期限超過と保留の行を抽出し、各担当に状況を確かめる。

**例外**: 同じ案件の判定保留が続けて残っている、部門の移管ステータスが埋まり移管の稟議を起票できる → §3.4、§4

### 3.7 進捗をまとめる

| 項目 | 内容 |
|---|---|
| 開始条件 | IT部門長に求められた、または部門の移管の稟議が承認された |
| 入力 | 予算移管シートの「モニタリング」、決定記録の「集計」 |
| 担当 | 進行役 |
| 期限 | 求められた日、または稟議の承認の後 |
| 出力 | 進捗のまとめ（IT部門長へ）、移管の稟議が承認された案件の一覧（Tier の運営主体へ） |

**作業**

1. 「モニタリング」の、移管ステータス別・移管判定別・部門別の集計を写す。
2. 「モニタリング」の、役割別のタスクの進捗（期限超過を含む）を写す。
3. 経過措置とした業務の件数と、手続きの完了予定を一覧にする。
4. 移管の稟議の状況（部門ごとの起票・承認）を加える。
5. 決定記録「集計」の、保留課題の件数と期限超過の件数を加える。
6. §4 の例外のうち、対応中のものを加える。
7. まとめを IT部門長に送る。
8. 移管の稟議が承認された部門の、一括移管の案件の一覧を、新しいITガバナンス（Tier）の運営主体に渡す。

## 4. 例外対応

案件ごとの例外（ヒアリング、判定保留、移管元の責任者の要望など）は、案件担当が一次対応し、進行役に伝える（案件担当編 §4）。進行役は、IT部門長へのエスカレーションをまとめて行う。

| 状況 | 一次対応 | エスカレーション先 | 詳細 |
|---|---|---|---|
| 予算シートがない部門がある | 移管対象部門の担当者に再度依頼し、経過を進捗のまとめに載せる | 移管元の責任者、IT部門長 | §3.2 |
| 案件のカウンターパートが決まらない | 候補を挙げて IT部門長に相談する | IT部門長 | §3.2 |
| 引継ぎ要領がキックオフまでに確定しない | 決まっていない項目と見込みを一覧にし、キックオフの扱いを相談する（予算移管の開始条件のため） | IT部門長 | §3.3 |
| 案件担当から例外の連絡を受けた | 内容と見込みを進捗のまとめに載せる | IT部門長 | 案件担当編 §4 |
| 「移管の稟議の完了期限」までに合意済みにならない案件がある | 案件担当と見込みを確かめる。IT関連業務の扱いが合意できないだけなら、その行を Before のまま（経過措置）として合意を進める | IT部門長 | §3.4 |
| 稟議が承認されない | 差し戻しの理由を一覧にし、案件担当と対応を決める | IT部門長 | §3.4 |
| 承認が期限までに得られない | 承認が得られない理由を一覧にする | IT部門長 | §1.5 |
| 進捗シートで期限超過・保留の行がある | 担当に状況と見込みを確かめ、進捗のまとめに載せる | IT部門長 | §1.6、§3.6 |

## 5. 記録とKPI

| 記録 | 置き場所 | 更新タイミング |
|---|---|---|
| 案件ごとの移管判定・移管ステータス・案件担当 | 予算移管シート「予算一覧」 | 各手順の完了時（移管ステータスは案件担当が更新する） |
