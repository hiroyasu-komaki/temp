## 1. 概要

### 1.1 目的

予算移管の全てのタスクを1つの表で見られるようにし、登場人物の全員について分担（RACI）を定める。各タスクの手順は、役割別の Runbook に定める。

| 文書 | 対象 |
|---|---|
| この文書（全体編） | 全体のタスク一覧と、全ての登場人物を含む RACI。分担は、この文書の §3 を正とする |
| [Runbook 進行役編](./08-runbook-01-transfer-lead.md)（BTR-P-08-01） | 進行役のタスク（P-）と、進行役が依頼する承認（A-05・A-08） |
| [Runbook 案件担当編](./08-runbook-04-case-owner.md)（BTR-P-08-04） | 案件担当のタスク（C-）と、案件担当が依頼する承認（A-03）。付録に引継ぎ要領 |

予算移管の実務は、進行役と案件担当の二者だけが行う（[憲章](../rules/02-charter.docx) 第6条）。それ以外の登場人物は、承認する、相談を受ける、連絡を受ける、のいずれかの立場で関わる。

### 1.2 登場人物

| 登場人物 | 立場 | 関わり方 |
|---|---|---|
| 進行役 | 実務（1名） | 全体と部門の単位の作業、移管の稟議、IT部門長への依頼 |
| 案件担当 | 実務（複数） | 案件の単位の作業、移管元の責任者への承認の依頼。普段からその案件でビジネス部門のカウンターパートを務めている IT部門のメンバー |
| 移管元の責任者 | 承認者（移管対象部門の部門長） | 合意文書（引継ぎの方法、IT関連業務の扱い、経過措置）と移管の稟議を承認する |
| 移管対象部門の担当者 | 情報の提供 | 予算シート・資料を提供し、ヒアリングに答え、記入内容を確かめる |
| IT部門長 | 承認者（機能の責任者） | 移管の稟議の承認、確認依頼・保留課題の決定 |
| ベンダーマネジメント担当 | 移管の後の受け手（契約） | 引継ぎ要領・引継ぎで相談を受け、移管の後に契約と委託先の管理を担う。請求書の宛名の変更を、1月度の請求に間に合うよう（2月初旬まで）各相手先に連絡する |
| 事務担当 | 移管の後の受け手（事務手続き） | 引継ぎ要領・引継ぎで相談を受け、移管の後に予算の管理と請求書の支払いを担う |
| 契約の相手先・委託先 | 社外 | 予算移管のタスクには関わらない。移管の後、ベンダーマネジメント担当から請求書の宛名の変更の連絡を受ける（署名者は次回の更新から IT部門に変わる） |
| 新しいITガバナンス（Tier）の運営主体 | 引き渡し先 | 移管の稟議が承認された案件の一覧を受け取る |

### 1.3 12月末のゴール

2026年12月末の時点で目指すのは、**移管の稟議が承認されていること**である（[憲章](../rules/02-charter.docx) 第3条第2項）。その前提として、次の3つがそろっていればよい。

| 前提 | 何がそろえばよいか | 対応する移管ステータス・タスク |
|---|---|---|
| (1) 稟議に必要な情報が整理されている | 案件ごとの移管判定と来年度予算が予算移管シートでそろい、合意文書が承認されている | 「合意済み」（C-05）、移管の稟議の起票（P-04） |
| (2) 12月末の時点で完了していないことが明確になっている | 経過措置とした業務（担当の変更に正式な手続きが要る業務。例：GxP の変更管理）の手続きの完了予定、契約の署名者の変更（次回の更新のとき）、請求書の宛名の変更（2月初旬まで）が、案件ごとに分かる | 「準備完了」（C-08。準備完了チェック No.3）、予算移管シート「業務」の変更管理の完了予定 |
| (3) 2027年1月から間接業務を始められる | 契約の管理と、請求書の支払いなどの事務手続きを、受け手（ベンダーマネジメント担当・事務担当）が1月から始められる | 「準備完了」（C-07・C-08。準備完了チェック No.2） |

担当の変更の手続き（SOPの改訂など）の完了、契約の署名者の変更、請求書の宛名の変更は、12月末のゴールに含めない。これらは2027年1月以降に、移管元の手順を変えずに間接業務を行いながら進める（憲章 第11条第3項・第5項）。

## 3. RACI

R＝実行、A＝最終責任、C＝相談、I＝連絡。A は1行に1つとする。ただし移管の稟議（A-05）は部門長同士の合意のため、移管元の責任者と IT部門長の両方を A とする。実務（R）は進行役と案件担当だけが持つ。

| No. | タスクID | タスク | 進行役 | 案件担当 | 移管元の責任者 | 移管対象部門の担当者 | IT部門長 | ベンダーマネジメント担当 | 事務担当 | 契約の相手先・委託先 | Tier の運営主体 |

| ① | P-01 | キックオフを開催する（IT部門内） | A/R | C | | | I | I | I | | |
| ② | P-02 | 予算シートを登録し、案件担当を割り当てる | A/R | I | | C | C | | | | |
| ③ | C-01 | ヒアリングで情報を集める | I | A/R | | C | | | | | |
| ④ | C-02 | 予算移管シートに記入する | | A/R | | C | | | | | |

- ⑥はタスク一覧の順番によらず、キックオフの前に終える（予算移管の開始条件）。
- ⑦⑩の案件担当の R には、経過措置とする業務（担当の変更に正式な手続きが要る業務）について、IT部門側の手順の改定を含めて移管対象部門の担当者と調整し、手続きを起票することを含む（憲章 第9条第3項・第10条第3項。手続きの完了は一括移管の後でよい）。
- ⑮の案件担当の R は、進行役の依頼を受けて自分の案件の移管ステータスを見直すこと（案件担当編 §3.10）。
- 契約の相手先・委託先は、予算移管のタスクには関わらない。移管の時点では契約について手続きを行わず、請求書の宛名の変更の連絡は、移管の後にベンダーマネジメント担当が行う（憲章 第11条第5項）。
- 移管の後の、直接業務と間接業務の分担（移管対象部門・ベンダーマネジメント担当・事務担当）は、[業務フロー定義](./06-process-definition.pptx) の RACI（3）による。
