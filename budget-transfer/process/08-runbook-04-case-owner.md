## 1. 概要

### 1.1 目的

予算移管の実務は、全体を進める **進行役**（1名）と、案件ごとの **案件担当**（複数）の二者で行う（[憲章](../rules/02-charter.docx) 第5条・第6条）。この文書は案件担当の手順を定める。案件担当は、普段からその案件でビジネス部門のカウンターパートを務めている IT部門のメンバーが、そのまま担う。

案件担当は、担当する案件について、ヒアリング、予算移管シートへの記入、判定保留の確認、引継ぎと IT関連業務の扱いの案（合意文書）の作成、合意の記録、間接業務の引継ぎ、準備完了の確認を行い、移管ステータスを随時更新する。移管ステータスがそろった部門から、進行役が移管の稟議を起票する。移管の時点では、契約について手続きを行わない（名義変更は不要。次回の更新のときに署名者が IT部門に変わり、請求書の宛名の変更はベンダーマネジメント担当が連絡する。憲章 第11条第5項）。キックオフ、案件の割当て、引継ぎ要領の整備、移管の稟議、IT部門長への依頼、進捗のまとめは進行役が行う（[Runbook 進行役編](./08-runbook-01-transfer-lead.md)）。

移管するのは予算・契約と、契約に基づく間接業務であり、移管対象部門の直接業務は扱わない（憲章 第4条第3項）。引き継いだ間接業務は、移管の後、ベンダーマネジメント担当（契約）と事務担当（請求書の支払いなどの事務手続き）が担う（憲章 第11条）。

### 1.2 対象範囲

| 対象 | 対象外 |
|---|---|
| 予算移管シート「予算一覧」で自分が案件担当になっている案件 | 他の案件担当の案件、全体の進行と稟議（進行役が行う）、移管の後の契約の精査、請求書の宛名の変更の連絡と支払い（受け手が行う） |

### 1.3 関係者

| 関係者 | 案件担当との関わり | 連絡先 |
|---|---|---|
| 進行役 | 案件の割当てと引継ぎ要領の確定の連絡を受け取る／合意文書と例外を伝える／稟議の結果を受け取る | — |
| 移管対象部門の担当者 | ヒアリングする／記入内容の確認を頼む／間接業務の資料を受け取る | 予算移管シート「窓口」に記録した担当者 |
| 移管元の責任者 | 合意文書（引継ぎの方法、IT関連業務の扱い、経過措置）の承認を求める | 予算移管シート「窓口」に記録した責任者 |
| ベンダーマネジメント担当・事務担当（移管の後の受け手） | 契約・事務手続きの扱いを相談する／引き継いだ間接業務を渡す | — |

### 1.4 責任（RACI）

[Runbook 全体編](./08-runbook-00-overview.md) §3 の RACI から、案件担当の分を抜き出したもの。分担そのものは全体編を正とする。全体のタスクの一覧は全体編 §2 にある。

| 活動 | 案件担当の役割 | 出典 |
|---|---|---|
| ③ ヒアリング（キックオフの前）、④ 記入、⑤ 部門の確認と判定保留の解消（キックオフの後） | A/R | 全体編 §3 |
| ⑦ 引継ぎと IT関連業務の扱いの案（合意文書）、⑧ 合意の記録 | A/R | 全体編 §3 |
| ⑩ 間接業務の引継ぎ、⑪ 準備完了の確認（⑨・⑬は欠番） | A/R | 全体編 §3 |
| ⑮ 移管ステータスの見直し（進行役の依頼による） | R | 全体編 §3 |
| 合意文書（承認の依頼と記録） | R | 全体編 §3 |
| ① キックオフ、⑥ 引継ぎ要領、⑫ 移管の稟議、確認依頼と保留課題 | C | 全体編 §3 |
| ② 割当て、移管の稟議の承認 | I | 全体編 §3 |

### 1.5 承認の依頼

移管元の責任者への案件ごとの承認は、案件担当が依頼し、記録する。IT部門長への依頼と稟議は進行役が行う（進行役編 §1.5）。

| 進捗の行 | 承認者 | 承認すること | 依頼する手順 | 承認の後に起きること |
|---|---|---|---|---|
| A-03 | 移管元の責任者 | 合意文書（間接業務の引継ぎの方法、IT関連業務の扱い、経過措置とその完了予定） | §3.4 | 合意を記録する（§3.5） |

同じ部門の案件を複数担当しているときは、承認の依頼をまとめてよい。

### 1.6 進捗の記録のしかた

1. 次のタイミングで、予算移管シート「進捗」に自分の案件の行を作る（担当者・期限を入れる）。

| タイミング | 作る行 |
|---|---|
| 案件の割当てを受けた（§3.1） | 案件ごとに C-01〜C-03 |
| 棚卸し済み（§3.3） | 案件ごとに C-04・C-05・A-03 |
| 合意済み（§3.5） | 案件ごとに C-07・C-08 |

2. 自分の行（C-01〜C-08。C-06 は欠番）の「状態」（未着手／進行中／完了／保留）と「完了日」を更新する。保留にしたときは、メモに理由を書く。
3. 承認の行（A-03）は、承認を得たときに更新する。承認者は記入しない。

### 1.7 12月末のゴール（案件担当から見た到達点）

12月末のゴールは、移管の稟議が承認されていることである（[Runbook 全体編](./08-runbook-00-overview.md) §1.3）。稟議は進行役が起票する。案件担当は、自分の案件について、次の状態を作る。

| 前提 | 自分の案件で作る状態 | 手順 |
|---|---|---|
| (1) 稟議に必要な情報が整理されている | 移管判定に判定保留がなく、合意文書が承認され、移管ステータスが「合意済み」 | §3.3〜§3.5 |
| (2) 完了していないことが明確になっている | 経過措置とする業務（担当の変更に正式な手続きが要る業務）の手続きが起票され、合意文書と「業務」シートに完了予定が入っている。契約の署名者の変更（次回の更新）と請求書の宛名の変更（2月初旬まで）のために、契約書の写しと相手先の請求の窓口が受け手に渡っている | §3.4、§3.7 |
| (3) 1月から間接業務を始められる | 移管する間接業務が受け手に引き継がれ、移管ステータスが「準備完了」 | §3.7、§3.8 |

SOPの改訂の完了、契約の署名者の変更、請求書の宛名の変更は、12月末までに終えなくてよい。

## 3. 手順

**進捗の記録**: 予算移管シート「進捗」の自分の行（C-01〜C-08）と、承認の行（A-03）を更新する（§1.6）。

### 3.1 ヒアリングで情報を集める

| 項目 | 内容 |
|---|---|
| 開始条件 | 年間カレンダー「ヒアリングの開始」になり、進行役から案件の割当てを受けた |
| 入力 | 予算一覧の自分の案件 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「ヒアリングの終了」（キックオフの前） |
| 出力 | システム・業務・契約の情報、一括移管への懸念・条件、受け取った資料 |

ヒアリングは、キックオフの前に行う事前の情報整理である。普段のカウンターパートとして、移管対象部門の担当者に聞き取る。部門の担当者の確認は、キックオフの後に §3.3 で得る。

部門向けの説明会は行わない（キックオフは IT部門内で行い、移管対象部門には案内済み）。部門への説明は、案件担当が次の範囲で行う。

| 伝える | 伝えない・約束しない |
|---|---|
| 予算移管の対象と流れ（[移管対象部門ガイド](../reference/12-handbook.pptx) の範囲）、このヒアリングが事前の情報整理であること、整理した内容の確認を11月にお願いすること | 移管するかどうかの希望（基準で決まり、聞かない。懸念・条件は聞く）、未定の事項（決定記録「保留課題」にあるもの。例: 変更依頼への回答期限、削減分を返す比率）、経過措置になるかどうかの見通し |

**作業**

1. §1.6 の行を「進捗」に作る。
2. 移管対象部門の担当者とヒアリングの日程を決める（1回60分程度、1〜2回。同じ部門の自分の案件はまとめて聞いてよい）。
3. 予算区分・投資の区分・システム関連が「未確認」の項目を確かめる。投資予算の案件は、今年度から続く案件か（継続）、来年度に始まる案件か（新規）を確かめる（憲章 第8条第3項）。
4. 案件ごとに、関係するシステムを聞き取る。
5. システムごとに、部門が行っている業務を聞き取り、予算移管シートの「業務の種類」のどれに当たるかを確かめる。
6. 業務ごとに、実施者・頻度・年間工数・GxP対象・個人情報・SOP有無を聞き取る。間接業務は、現場の関わり方も聞き取る。今の役割分担が SOP・規程・職務分掌など承認済みの文書や記録で定められている業務は、その文書と、担当の変更に要る手続き（例：GxP の変更管理）の見込みも聞き取る（§3.4 の準備）。IT関連業務（中間層）は、今のやり方（Before）を聞き取る。
7. 契約ごとに、契約名・相手先・契約種別・期間・自動更新・解約予告・年間金額と、管理している業務を聞き取る。
8. 支払いの時期と方法を聞き取る。
9. 一括移管への懸念・条件を聞き取る。
10. 契約書の写し、システム構成図・設計書、運用手順書・SOP、委託先からの報告書のうち、手元にあるものを受け取る。
11. ヒアリングの記録と受け取った資料を、事業部門と IT部門の双方が編集できる SharePoint フォルダに置く。

継続している投資案件は対象外になるので、手順4以降は聞かなくてよい（1回限りの支出の発注・検収は、移管対象部門が行う）。

**例外**: 担当者が答えられない項目がある → §4

### 3.2 予算移管シートに記入する

| 項目 | 内容 |
|---|---|
| 開始条件 | 案件のヒアリングが終わった |
| 入力 | ヒアリングの記録、受け取った資料 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「ヒアリングの終了」 |
| 出力 | 予算一覧の未確認の項目、「紐付け」「システム」「業務」「契約」の各シートの行 |

**作業**

1. 予算一覧の、予算区分・投資の区分・システム関連の「未確認」を直す。
2. 「紐付け」シートに、案件とシステムの対応を1行ずつ記入する。
3. 「システム」シートに、システムの基本情報を記入する。同じシステムが他の案件担当の案件にも紐づくときは、先に登録された行を使い、その案件担当に知らせる。
4. 「業務」シートに、業務を1行ずつ記入し、案件ID・対象システムIDを入れ、業務の種類を選ぶ（業務区分は自動で決まる）。同じシステムが他の案件に紐づいていても、自分の案件の業務は自分の行として書き、他の案件担当の行は変えない。経費予算の案件は、紐付けたシステムごとに、その案件の間接業務を1行以上書く（1つの契約で複数のシステムをまかなう場合も、システムごとに「予算の管理」などの行を作る）。1行もないシステムがあると、間接業務の移管判定（AN）が判定保留のままになる。
5. 契約を管理する業務に、関連契約IDを記入する。
6. 「契約」シートに、契約の基本情報と案件IDを記入する。1つの契約を複数の案件の予算から払う場合（投資予算と経費予算で行を分けた案件を含む）は、案件ごとに契約の行を分け、契約IDに枝番を付ける（例: CT-2201-1、CT-2201-2）。年間契約金額は、その案件が払う分を書く。業務の関連契約IDには、その業務の案件の枝番を書く。
7. 予算一覧の「移管対象部門のコメント」に、一括移管への懸念・条件を記入する。

新規の投資案件は、次のとおり記入する（間接業務の移管判定は「—」になり、業務は判定に使わない。仕様 §3.3）。

| シート | 記入するか |
|---|---|
| 予算一覧 | 予算区分「投資予算」、投資の区分「新規」、システム関連を記入する |
| 紐付け・システム | 既存のシステムの改修なら記入する。新規導入でシステムがまだない場合は記入しない |
| 業務 | 記入しない（発注・検収ははじめから IT部門が行う） |
| 契約 | 締結済み・締結予定の契約があれば記入する（紐づく業務が0件でよい） |
部門の担当者への確認の依頼と、業務の「棚卸し」を「済」にするのは、キックオフの後に §3.3 で行う。経過措置の完了予定（「業務」シート S列）は、§3.4 で記入する。

### 3.3 判定保留を確認し、棚卸しを終える

| 項目 | 内容 |
|---|---|
| 開始条件 | 年間カレンダー「キックオフ」が終わった（記入は §3.2 で済んでいる） |
| 入力 | §3.2 で記入した内容、予算一覧の移管判定、「契約」シートの紐づく業務数 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「合意の期限」に間に合うように（§3.4 に入る前） |
| 出力 | 部門の確認、確認する項目の一覧（判定保留が残る場合）、移管ステータス「棚卸し済み」または「対象外」 |

**作業**

1. 記入した内容を移管対象部門の担当者に送り、確認を依頼する。
2. 確認が済んだ業務の「棚卸し」を「済」にする。
3. 予算一覧で、自分の案件の移管判定（予算）が判定保留かを確かめる。
4. 判定保留なら、紐付け → システム → 業務 → 契約の順にたどり、足りない入力を一覧にする。
5. 「契約」シートで、紐づく業務数が0件の、自分の案件の契約を一覧に加える（経費予算の案件だけ。新規の投資予算の契約は、業務がなくてよい）。
6. 一覧を担当者に送って答えを得て、§3.2 の要領で記入を直す。
7. 移管判定（予算）が「対象外」なら、移管ステータスを「対象外」にし、ステータス更新日を記入する。
8. 判定保留がなく、記入内容の確認が済んだ案件の移管ステータスを「棚卸し済み」にし、ステータス更新日を記入する。棚卸しの結果について、移管元の責任者の承認は要さない（移管するかどうかは基準で決まる。憲章 第8条）。
9. 「進捗」の C-03 を完了にし、§1.6 の行を「進捗」に作る。

**例外**: 担当者の確認が得られない、判定保留が解消せず §3.4 に入れない → §4

### 3.4 引継ぎと IT関連業務の扱いの案（合意文書）を作る

| 項目 | 内容 |
|---|---|
| 開始条件 | 案件の移管ステータスが「棚卸し済み」になった |
| 入力 | 予算一覧、「業務」「契約」シート、[標準 RACI](../appendix/01-post-transfer-operating-model.md)（BTR-APX-01 §5）、付録「引継ぎ要領」 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「合意の期限」 |
| 出力 | 合意文書の案（案件ごとにカスタマイズした RACI、経過措置とその完了予定、間接業務の引継ぎの方法） |

予算は、全ての案件で一括移管の実施日（2027-01-01）に移す（憲章 第9条）。この手順では、移管の後の役割分担を案件ごとに合意する。

**作業**

1. 標準 RACI の Before と、ヒアリングで聞き取った今のやり方を比べる。違えば、その案件の Before を書き直す。
2. 標準 RACI の After をもとに、IT関連業務（中間層）の行について、R と C を BU と SO のどちらが持つか、SO が R を持ち始める時期を案にする。変えてよいのはこの範囲だけで、A の列と、直接業務・間接業務の行は変えない（BTR-APX-01 §5.3）。標準と違うところは、理由と見直しの時期を書く。
3. 今の役割分担が承認済みの文書や記録で定められていて、担当を変えるのに正式な手続き（例：GxP の変更管理）が要る業務を洗い出す。その業務は、手続きが完了するまで今の担当のまま行う（経過措置。憲章 第9条第3項）。手続きの内容と完了予定を、合意文書と「業務」シートの S列・T列に書く。IT部門側の手順の改定は、移管対象部門の担当者と調整して、その手続きに含める。
4. 付録「引継ぎ要領」に沿って、間接業務の引継ぎの方法をまとめる。
5. 1〜4 を合意文書としてまとめ、移管元の責任者に送り、承認を依頼する（§1.5 の A-03）。
6. 合意文書の写しを進行役に送る（進行役が全案件を横並びで確かめる）。

**例外**: 移管元の責任者が移管しないことを求める、IT関連業務の扱いが合意できない → §4

### 3.5 合意を記録する

| 項目 | 内容 |
|---|---|
| 開始条件 | 移管元の責任者が合意文書を承認した |
| 入力 | 承認された合意文書 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「合意の期限」 |
| 出力 | 保存した合意文書、決定記録の行、移管ステータス「合意済み」 |

**作業**

1. 承認された合意文書を、事業部門と IT部門の双方が編集できる SharePoint フォルダに保存する。
2. 経過措置とした業務に、「業務」シートの S列（完了予定）と T列（手続きの内容）が入っていることを確かめる。
3. 承認を、[決定記録](../reference/15-decision-log.xlsx)「決定事項」に登録する。
4. 移管ステータスを「合意済み」にし、ステータス更新日と「進捗」の A-03 を更新する。
5. §1.6 の行を「進捗」に作る。
6. 進行役に、合意済みにしたことを連絡する（移管の稟議の起票に使う）。

**例外**: 「合意の期限」までに合意できない → §4

### 3.6 （欠番）

契約の名義変更の手配（旧 C-06）は廃止した。移管の時点では、契約について手続きを行わない。移管した契約は、次回の更新のときに署名者が IT部門に変わる。請求書の宛名の変更は、ベンダーマネジメント担当が、1月度の請求に間に合うよう（2月初旬まで）各相手先に連絡する（憲章 第11条第5項）。案件担当は、§3.7 で契約書の写しと相手先の請求の窓口を受け手に渡す。

### 3.7 間接業務を引き継ぐ

| 項目 | 内容 |
|---|---|
| 開始条件 | 案件の移管ステータスが「合意済み」になった |
| 入力 | 予算移管シート「業務」「契約」、付録「引継ぎ要領」、移管対象部門から受け取った手順・資料・未払いの請求 |
| 担当 | 案件担当 |
| 期限 | 年間カレンダー「準備完了の確認の期限」 |
| 出力 | 受け手に渡した間接業務の手順・資料 |

**作業**

1. 「業務」シートで、自分の案件の、業務移管判定が「移管」の間接業務を抽出する。
2. 付録2「受け取るもの」に沿って、間接業務ごとに、移管対象部門から手順・資料（契約書の写し、相手先の請求の窓口、SOP、未払いの請求、支払いの時期、委託先の連絡先など）を受け取る。
3. 受け取ったものを、付録1の受け手（契約はベンダーマネジメント担当、事務手続きは事務担当）に渡し、2027年1月から受け手が始められることを確かめる。
4. 経過措置とした業務は、担当の変更の手続きが起票され、「業務」シートに完了予定が入っていることを確かめる（準備完了チェック No.3）。手続きが完了するまでは、その業務は今の担当と手順のまま行う。
5. 引継ぎが済んだら、「進捗」の C-07 を完了にする。

**例外**: 資料が手に入らない、受け手が受け取れない → §4

## 付録 引継ぎ要領

案件担当が、移管対象部門から間接業務を受け取り、受け手に渡すときの決まり。進行役が受け手（ベンダーマネジメント担当・事務担当）と確かめて、キックオフの前に確定させる（進行役編 §3.3。予算移管の開始条件）。IT部門長の承認は要さない。案件担当は §3.4・§3.7 で使う。

- 移管の直後は、移管元の手順（発注・検収・支払いの手順、委託先への指示の方法）を変えずに引き継ぐ（憲章 第11条第3項）。GxP対象の間接業務は、変更管理が完了するまで移管元の手順のまま行う。
- 移管の後の契約の精査や請求書の支払いの手順そのものは、受け手が定める。この要領では扱わない。

### 付録1 受け手の対応表

| 間接業務の種類 | 受け手 | 移管の後に受け手が行うこと |
|---|---|---|
| 予算の管理 | 事務担当 | 予算の計上・執行・管理 |
| 契約の管理（締結・更新・解約） | ベンダーマネジメント担当 | 契約の締結・更新・変更・解約 |
| 発注・検収・支払い | 事務担当 | 発注・検収・支払いの手続き（業務要件を満たすかの確認は、移管対象部門の直接業務） |
| 委託先の管理（指示・報告の確認） | ベンダーマネジメント担当 | 委託先への指示、報告の確認 |
| 契約に関する監査・規制対応 | ベンダーマネジメント担当（事務担当が協力） | 監査・規制対応の窓口 |

### 付録2 受け取るもの

| 区分 | 移管対象部門から受け取るもの | 渡す先 |
|---|---|---|
| 契約 | 契約書の写し（変更契約・覚書を含む）、満了日・自動更新・解約予告、相手先の窓口と請求の窓口（請求書の宛名の変更の連絡に使う） | ベンダーマネジメント担当 |
| 委託先 | 委託先の連絡先、定例・報告の形式と頻度、直近の報告書、未解決の課題 | ベンダーマネジメント担当 |
| 支払い | 発注の手続き、支払いの時期と方法、直近の請求書、未払いの請求 | 事務担当 |
| 予算 | 来年度予算（月別）と執行の見込み | 事務担当 |
| GxP | 対象の間接業務の SOP、変更管理の記録（憲章 第10条第3項） | その間接業務の受け手 |

### 付録3 請求書の宛名の変更

移管の時点では、契約について手続きを行わない。移管した契約は、次回の更新のときに署名者が IT部門に変わる。請求書の宛名の変更は、ベンダーマネジメント担当が、1月度の請求に間に合うよう（2月初旬まで）各相手先に連絡する（憲章 第11条第5項）。案件担当は、付録2の「契約」を渡すときに、相手先の請求の窓口を添える。
