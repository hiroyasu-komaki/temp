## 1. 全体構成

```
[利用者の PC]  ブラウザ（Edge／Chrome）または Teams のタブ
   │
   ├─ アプリ①「IT投資 申請」（Power Apps キャンバスアプリ・日英）
   │     申請画面、マイ申請、案件リスト、案件の閲覧      ← 全員
   │
   └─ アプリ②「審議ワークベンチ」（Power Apps キャンバスアプリ・日本語）
         担当割当、論点整理書の登録、確認表、回答書、結果確定  ← 事務局・審査担当者・委員会・PPM
   │
   │ 読み取り：SharePoint コネクタで直接（利用者の権限）
   │ 書き込み：Power Automate を呼ぶ（Power Apps (V2) トリガー）
   ▼
[処理]  Power Automate クラウドフロー（CMS 専用のサービスアカウントで実行）
   ├ 画面の操作ごとのフロー F01〜F23、子フロー C01〜C06、定期実行 S01〜S03
   ├ 通知：Teams（フロー ボットのカード）＋ Outlook（共有メールボックスから送信）
   ├ AI：案件概要書の自動生成 ………… 方式は保留（#T5）
   └ PDF：案件概要書の PDF 出力 ………… 方式は保留（#T14）
   ▼
[データ]  SharePoint Online（CMS 専用サイト）
   ├ リスト：Cases、CaseSummaries、ReviewChecks、Comments、CaseEvents、Drafts、マスタ5種
   └ ライブラリ：CaseDocuments、TempUploads
```

## 2. 技術選定一覧

| レイヤー | 採用技術 | バージョン方針 | 選定理由 | 却下した候補と理由 |
|---|---|---|---|---|
| 画面 | Power Apps キャンバスアプリ（2本。ADR-0006） | 常に最新（SaaS） | 申請画面の自由なレイアウト（自動生成・出所表示・食い違いの選択）が作れる。Teams に載せられる | モデル駆動型アプリ：Dataverse が前提で追加ライセンスが要る。SharePoint リストのフォーム：自動生成や複雑な画面が作れない。Microsoft Forms：自動入力ができない（ADR-0004） |
| 部品化 | Power Apps のコンポーネントライブラリ | − | 2本のアプリで見出し・ステータス表示・エラー表示を共通化する | コード部品（PCF）：プレミアムライセンスが要る |
| 処理 | Power Automate クラウドフロー（ソリューション内） | − | 状態と権限の検証をサーバ側で必ず行える（ADR-0005）。標準コネクタで SharePoint・Teams・Outlook を扱える | Azure Functions 等：開発・運用の体制が要る。Power Apps から直接書き込み：ルールを画面でしか守れない |
| データ | SharePoint Online のリスト | − | 追加ライセンス不要。件数（年120件・3年保持）に対して十分（ADR-0001） | Dataverse：利用者全員にプレミアムライセンスが要る。Excel：同時更新と権限制御に向かない |
| ファイル | SharePoint Online のドキュメントライブラリ | − | バージョン履歴・ごみ箱・閲覧権限を標準で持つ | OneDrive：個人の持ち物になり、異動・退職で消える |
| 認証・権限 | Microsoft Entra ID（M365 サインイン）＋ SharePoint グループ | − | CMS 独自の認証を持たない。ロールは SharePoint グループで管理 | Entra ID のセキュリティグループのみ：グループ作成に IT 部門の手続きが要る（併用は可） |
| 通知 | Teams（フロー ボットのカード）＋ Outlook（共有メールボックス） | − | 社内の連絡手段に合わせる。差出人を個人でなく CMS にする | 個人のメールボックスから送信：異動・退職で止まる |
| 翻訳 | SharePoint リスト UiStrings（日英） | − | 文言を後から直せる。範囲は申請画面と案件リスト（決定ログ #21） | アプリへの直書き：翻訳・修正のたびにアプリの改修が要る |
| AI（自動生成） | **保留（#T5）** | − | 候補：AI Builder のプロンプト、Copilot Studio のエージェント、Azure OpenAI。F02 GenerateSummary の中だけで使うので、決まれば差し込める | − |
| PDF 出力 | **保留（#T14）** | − | 候補：フローで HTML を組み立て OneDrive の変換で PDF にする、Word テンプレートに差し込む。F04 の中だけで使う | − |
| 構築の自動化 | SharePoint：PnP PowerShell のプロビジョニングテンプレート。Power Platform：ソリューション | − | リスト・列・索引・権限を手作業で作らない（データモデル §9）。環境をまたいで同じものを作れる | 手作業＋手順書：索引の作り忘れ・列名の揺れが起きる |
| ソース管理 | Git（ソリューションを展開したファイルと、PnP テンプレート、JSON スキーマ、本ドキュメント） | − | 変更の履歴と差分を追える | ソリューションの zip だけを保管：差分が見えない |
| 変更の管理 | 本番環境だけで作り、変更は手順（変更前のコピー、業務時間外の反映、動作確認）に従う（§4） | − | 環境を分けない（決定ログ #23） | 開発・本番の分離：環境を用意できない見込み（#T26） |

## 3. 中核となる設計原則

### 原則1：書き込みはフローだけ

- 要求すること：データを変える操作は、必ずフロー（F・S）を呼ぶ。フローは C02 GuardCase で状態・更新日時・実行者を確かめてから書く。
- 禁止すること：Power Apps から Cases 以下のリスト・ライブラリへ `Patch`／`SubmitForm` で直接書くこと。
- 例外：Drafts（下書き）だけは、利用者本人が Power Apps から直接保存する（ADR-0005）。

### 原則2：標準コネクタだけで作る

- 要求すること：SharePoint、Office 365 Outlook、Microsoft Teams、Office 365 Users、承認など、Microsoft 365 のライセンスで使えるコネクタだけを使う。
- 禁止すること：プレミアムコネクタ、HTTP コネクタ、Dataverse、コード部品（PCF）。
- 例外：AI の呼び出し（#T5）。決まったら ADR を起こし、その範囲だけに閉じ込める。

### 原則3：変わる値はリストで持つ

- 要求すること：期限の日数、委員長・代理、休日、部門、ケイパビリティと担当、画面の文言（日英）は、Settings・Holidays・Departments・Capabilities・UiStrings から読む。
- 禁止すること：これらをアプリやフローに直接書くこと。
- 例外：なし。

### 原則4：状態と選択肢はコード値で持つ

- 要求すること：Status・選択肢は英字のコード（`BRIEFING` など）で保存し、表示名は翻訳表から引く。
- 禁止すること：日本語の表示名を保存値として比較・判定に使うこと。
- 例外：なし。

### 原則5：SharePoint 側で絞り込める検索だけを書く

- 要求すること：一覧・検索は索引付きの列を使い、Power Apps が SharePoint 側で絞り込める条件（等号、StartsWith など）で書く（データモデル §7）。
- 禁止すること：件数が増えると結果が欠ける書き方（先頭の最大 2,000 件しか見ない検索）。
- 例外：マスタ（件数が少ないもの）。

## 4. 環境

**本番環境だけを想定する**（決定ログ #23）。開発用の SharePoint サイトや Power Platform 環境は置かない。

| 項目 | 方針 |
|---|---|
| SharePoint サイト | CMS 本番サイト 1つ |
| Power Platform | 本番の環境に、アプリ2本とフローを置く |
| 接続 | サービスアカウントの接続だけ（接続参照） |
| 試験 | 稼働前に本番サイトで試験データを使って受入試験を行い、稼働前に試験データを削除する（件数上限の確認用に件数を増やしたデータも使う） |
| 稼働後の変更 | アプリはバージョン履歴で戻せる状態を保ち、変更は業務時間外に反映する。フローは変更前にコピーを残す。手順は 08-operations |
| リスク | 本番で直接変更するため、誤った変更がすぐ利用者に影響する → 変更前のコピー、変更後の動作確認、戻し方を手順化する |

## 5. 外部依存・前提サービス

| 依存先 | 用途 | 提供者 | 提供予定時期 | 揃わない場合の代替 |
|---|---|---|---|---|
| CMS 専用サービスアカウント（M365 ライセンス付き） | フローの実行、書き込み、通知 | IT部門 | 開発開始前（決定ログ #19） | なし（ADR-0005 の前提） |
| SharePoint サイト（本番） | データ | IT部門（SharePoint 管理者） | 開発開始前 | − |
| Power Platform の本番環境 | アプリ・フローの置き場所 | IT部門（Power Platform 管理者） | 開発開始前 | − |
| 共有メールボックス（CMS の差出人） | 通知メール | IT部門（Exchange 管理者） | 受入試験前 | サービスアカウントのメールボックスから送る |
| PnP PowerShell を使うためのアプリ登録（Entra ID） | SharePoint の構築の自動化 | IT部門（管理者の同意） | 構築開始前 | 手順書による手作業（索引を最初に作る） |
| AI サービス | 案件概要書の自動生成 | #T5 で決定 | 保留 | 自動生成なしで手入力（申請画面は動く） |
| PDF 生成 | 案件概要書の PDF | #T14 で決定 | 保留 | ブラウザの印刷機能で代替 |

## 6. 部品・追加機能の方針

| 領域 | 方針 |
|---|---|
| 外部の部品 | 使わない（コード部品・外部ライブラリなし）。Power Apps・Power Automate の標準機能とコンポーネントライブラリだけで作る |
| ライセンス | Microsoft 365 のライセンスの範囲で作る。プレミアムが必要になる機能は ADR を起こして判断する（AI は #T5） |
| 新しいコネクタ・機能を足すとき | CMS 管理者の承認。プレミアムに当たらないか、データが社外に出ないかを確認する |
