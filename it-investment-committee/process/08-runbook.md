## 1. 概要

### 1.1 目的

本Runbookは、IT投資委員会事務局が行う、Tier1・Tier2の運営と、IntakeForm・実行計画の受付から決定の記録・通知までの手順を定める。Tier3の運営はTier3の主催者が行い、IT投資委員会事務局は招集の依頼と推奨案の受け取りだけを行う。Tier2が実行計画の決裁を承認会議（ローカル）に委ねた案件は承認会議（ローカル）が承認・否認を決め、IT投資委員会事務局は委任の通知と結果の受け取りだけを行う。

### 1.2 対象範囲

| 対象 | 対象外 |
|---|---|
| 年次の優先順位付け（Tier1・Tier2）の運営（§3.1〜§3.4） | Tier3の運営（Tier3の主催者が行う） |
| 随時のIntakeの優先度の審議（Tier1・Tier2）の運営（§3.5〜§3.7） | 優先順位・優先度が付いた案件の管理と、実行計画の作成・提出の通知（PPMボードが行う）。起案者への実行計画の作成・提出の依頼（起案者の所属部門が行う） |
| 実行計画の審議（Tier2）の運営と、Tier3の招集の依頼・承認会議（ローカル）への委任の通知（§3.8〜§3.13） | 年次のIT投資予算の総額の提示（ファイナンス部門が行う） |
| | 承認会議（ローカル）に委ねた案件の実行計画の承認・否認（承認会議（ローカル）が行う） |

## 2. 年間の流れ

月は目安とし、日付は（TBD: 年次の受付期間と年次の会議の日程）による。随時のIntakeは、年次の予算策定とは別に、時期を問わず受け付ける。

| 時期（相対） | 作業 | 参照する手順 |
|---|---|---|
| 年次の受付期間の前 | 年次の受付を周知する | §3.1 |
| 年次の受付期間中 | 年次の提出を確認する | §3.2 |
| 年次の受付期間の後、11月ごろのTier1・Tier2の年次の会議まで | 年次の会議を運営する | §3.3 |
| 年次の会議の議事録の確定後 | 優先順位を記録し通知する | §3.4 |
| 12月（来期予算の確定と同時） | （事務局の作業はない。PPMボードが起案者の所属部門（事業部門またはIT部門）に実行計画の提出期限を通知し、所属部門が起案者に作成・提出を依頼する） | — |
| 随時（IntakeFormを受け取ったとき） | Intakeを受け付ける／Intakeの会議を運営する／優先度を記録し通知する | §3.5〜§3.7 |
| 1月から（実行計画を受け取ったとき。随時のIntakeで優先度ありとなった案件は、その後随時） | 実行計画を受け付ける／Tier2を運営する／審議結果を記録し通知する | §3.8〜§3.10 |
| 随時（Tier2がTier3の招集を要請したとき） | Tier3の招集を依頼する／Tier2の再審議を運営する | §3.11〜§3.12 |
| 随時（Tier2が決裁を承認会議（ローカル）に委ねたとき） | 承認会議（ローカル）への委任を通知し、結果を受け取る | §3.13 |

## 3. 手順

### 3.1 年次の受付を周知する

| 項目 | 内容 |
|---|---|
| 開始条件 | 年次の予算策定のイベントの日程が決まった |
| 入力 | 年次の予算策定のイベントの日程（（TBD: 年次の受付期間と年次の会議の日程））、IntakeForm |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 年次の受付の周知 |

**作業**

1. 年次の受付期間と、Tier1・Tier2の年次の会議の日程を確認する。
2. IntakeFormの最新版を提出先（（TBD: IntakeFormの置き場所と提出先））に置く。
3. 起案者に、年次の受付期間・提出先・IntakeFormの置き場所を周知する。
4. 周知した日と周知先を案件台帳に記録する。

**例外**: 年次の会議の日程が変わった → §4

### 3.2 年次の提出を確認する

| 項目 | 内容 |
|---|---|
| 開始条件 | 年次の受付期間に、起案者がIntakeFormを提出した |
| 入力 | IntakeForm |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 案件ID、案件台帳の新規行、差し戻しの連絡（不足がある場合） |

**作業**

1. 案件台帳に案件を登録し、案件IDを振る。
2. IntakeFormに[運用基準](../rules/03-standard.docx) 第8条の必須の情報がそろっているかを確認する。
3. 必須の情報に不足がある場合は、不足する項目を起案者に伝えて差し戻す（[運用基準](../rules/03-standard.docx) 第9条）。
4. 不足がない場合は、[運用基準](../rules/03-standard.docx) 第5条により付議先（Tier1またはTier2）を案件台帳に記録する。
5. 起案者に、受付を完了したことと付議先を通知する。

**例外**: 受付期間を過ぎて提出された／付議先の判定が分かれる → §4

### 3.3 年次の会議を運営する

| 項目 | 内容 |
|---|---|
| 開始条件 | 年次の受付期間が終わった |
| 入力 | 案件台帳（付議先が記録された案件）、ファイナンス部門が提示した年次のIT投資予算 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | Tier1・Tier2の議題・資料・議事録 |

**作業**

1. 付議先ごとに、案件の一覧を作る。
2. 一覧に、ファイナンス部門が提示した年次のIT投資予算を添える。
3. Tier1の議長とTier2の議長に、それぞれの議題を確定してもらう。
4. 各会議体の構成員に、開催案内と資料を送る。
5. 会議に出席し、決定した優先順位を記録する。
6. 議事録を作成し、議長の確認を受ける。

**例外**: 議長が議題を確定しない／会議が定足数に達しない → §4

### 3.4 優先順位を記録し通知する

| 項目 | 内容 |
|---|---|
| 開始条件 | Tier1・Tier2の年次の会議の議事録が確定した |
| 入力 | 議事録 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 決定記録の行、起案者への通知、PPMボードへの優先順位の一覧 |

**作業**

1. 決定した優先順位を、[決定記録](../reference/15-decision-log.xlsx)「決定事項」に1件1行で登録する。
2. 案件台帳に、優先順位を記録する。
3. 起案者に、優先順位を通知する。
4. 優先順位の一覧をPPMボードに渡す（（TBD: 決定の連携先と方法（PPMボード・ファイナンス部門）））。
5. 議事録を案件台帳と同じ場所に保管する。

**例外**: 起案者が決定に異議を出した → §4

### 3.5 Intakeを受け付ける

| 項目 | 内容 |
|---|---|
| 開始条件 | 起案者が、年次の予算策定とは別に、IntakeFormを提出した（随時のIntakeは、時期を問わず受け付ける） |
| 入力 | IntakeForm |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 案件ID、案件台帳の新規行、差し戻しの連絡（不足がある場合） |

**作業**

1. 案件台帳に案件を登録し、案件IDを振る。
2. IntakeFormに[運用基準](../rules/03-standard.docx) 第8条の必須の情報がそろっているかを確認する。
3. 必須の情報に不足がある場合は、不足する項目を起案者に伝えて差し戻す（[運用基準](../rules/03-standard.docx) 第9条）。
4. 不足がない場合は、[運用基準](../rules/03-standard.docx) 第5条により付議先（Tier1またはTier2）を案件台帳に記録する。
5. 起案者に、受付を完了したことと付議先を通知する。あわせて、年次のIT投資予算への追加は原則として認められないことを伝える（[運用基準](../rules/03-standard.docx) 第5条第3項）。

**例外**: 付議先の判定が分かれる → §4

### 3.6 Intakeの会議を運営する

| 項目 | 内容 |
|---|---|
| 開始条件 | 随時のIntakeの受付を完了した |
| 入力 | IntakeForm、案件台帳 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | Tier1またはTier2の議題・資料・議事録 |

**作業**

1. 付議先の会議体の議長に、開催を依頼する。
2. 議長と開催日を確定する。
3. 構成員に、開催案内とIntakeFormを送る。
4. 会議に出席し、優先度の判断（優先度あり／優先度なし）を記録する。
5. 議事録を作成し、議長の確認を受ける。

**例外**: 議長が開催日を確定しない／会議が定足数に達しない → §4

### 3.7 優先度を記録し通知する

| 項目 | 内容 |
|---|---|
| 開始条件 | 随時のIntakeの会議の議事録が確定した |
| 入力 | 議事録 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 決定記録の行、起案者への通知、PPMボードへの連絡（優先度ありの場合） |

**作業**

1. 優先度の判断を、[決定記録](../reference/15-decision-log.xlsx)「決定事項」に登録する。
2. 案件台帳に、優先度の判断を記録する。
3. 起案者に、優先度の判断と次に行うこと（[運用基準](../rules/03-standard.docx) 第10条）を通知する。
4. 優先度ありの場合は、PPMボードに案件を渡す（（TBD: 決定の連携先と方法（PPMボード・ファイナンス部門）））。
5. 議事録を案件台帳と同じ場所に保管する。

**例外**: 起案者が決定に異議を出した → §4

### 3.8 実行計画を受け付ける

| 項目 | 内容 |
|---|---|
| 開始条件 | 起案者が、PPMボードの通知を受けた起案者の所属部門（事業部門またはIT部門）の依頼により、または依頼に先行して、実行計画を提出した（実行計画は、起案者がIT部門の担当者と共同で作成する） |
| 入力 | 実行計画、案件台帳（優先順位・優先度） |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 案件台帳の受付の記録、差し戻しの連絡（不足がある場合） |

**作業**

1. 案件台帳で、案件に優先順位または優先度ありの判断が付いていることを確認する。
2. 実行計画に[運用基準](../rules/03-standard.docx) 第8条の必須の情報がそろっているかを確認する。
3. 必須の情報に不足がある場合は、不足する項目を起案者に伝えて差し戻す（[運用基準](../rules/03-standard.docx) 第9条）。
4. 不足がない場合は、実行計画の受付を案件台帳に記録する。
5. 起案者に、受付を完了したことを通知する。

**例外**: 優先順位の付いていない案件の実行計画が提出された → §4

### 3.9 Tier2を運営する

| 項目 | 内容 |
|---|---|
| 開始条件 | 実行計画の受付を完了した |
| 入力 | 実行計画、案件台帳 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | Tier2の議題・資料・議事録 |

**作業**

1. Tier2の議長に議題を確定してもらう（定常の開催は月1回）。
2. 構成員に、開催案内と実行計画を送る。
3. 会議に出席し、決定（承認／否認、Tier3の招集の要請、または承認会議（ローカル）への委任。[運用基準](../rules/03-standard.docx) 第5条第2項）を記録する。
4. 議事録を作成し、議長の確認を受ける。

**例外**: 議長が議題を確定しない／会議が定足数に達しない → §4

### 3.10 審議結果を記録し通知する

| 項目 | 内容 |
|---|---|
| 開始条件 | Tier2が実行計画の承認または否認を決め、議事録が確定した。または、承認会議（ローカル）から承認・否認の結果を受け取った（§3.13） |
| 入力 | 議事録 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 決定記録の行、起案者への通知、PPMボードへの審議結果 |

**作業**

1. 審議結果（承認／否認）を、[決定記録](../reference/15-decision-log.xlsx)「決定事項」に登録する。
2. 案件台帳に、審議結果を記録する。
3. 起案者に、審議結果と次に行うこと（[運用基準](../rules/03-standard.docx) 第10条）を通知する。
4. 審議結果をPPMボードに渡す（（TBD: 決定の連携先と方法（PPMボード・ファイナンス部門）））。
5. 議事録を案件台帳と同じ場所に保管する。

**例外**: 起案者が決定に異議を出した → §4

### 3.11 Tier3の招集を依頼する

| 項目 | 内容 |
|---|---|
| 開始条件 | Tier2がTier3の招集を要請した |
| 入力 | Tier2の議事録（要請の内容）、実行計画 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | Tier3の主催者への招集の依頼 |

**作業**

1. Tier3の主催者に、Tier3の招集を依頼する（（TBD: Tier3の招集の方法と任命者））。
2. Tier3の主催者に、実行計画とTier2の要請の内容を渡す。
3. Tier3の主催者に、推奨案の報告の期限（[運用基準](../rules/03-standard.docx) 第13条）を伝える。
4. Tier3の審査を依頼したことを案件台帳に記録する。
5. 起案者に、Tier3で審査することを通知する。

**例外**: 推奨案が期限までに届かない → §4

### 3.12 Tier2の再審議を運営する

| 項目 | 内容 |
|---|---|
| 開始条件 | Tier3の主催者から推奨案を受け取った |
| 入力 | 推奨案、実行計画 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | Tier2の議題・資料・議事録 |

**作業**

1. 推奨案を受け取ったことを、案件台帳と[決定記録](../reference/15-decision-log.xlsx)「決定事項」（判断区分: 報告受領）に登録する。
2. Tier2の議長に推奨案を渡し、再審議の開催を依頼する。
3. 議長と開催日を確定する。
4. 構成員に、開催案内と実行計画・推奨案を送る。
5. 会議に出席し、決定（承認／否認）を記録する。
6. 議事録を作成し、議長の確認を受ける。

**例外**: 議長が開催日を確定しない／会議が定足数に達しない → §4

### 3.13 承認会議（ローカル）への委任を通知し、結果を受け取る

| 項目 | 内容 |
|---|---|
| 開始条件 | Tier2が、実行計画の決裁を承認会議（ローカル）に委ねた（[運用基準](../rules/03-standard.docx) 第5条第2項） |
| 入力 | Tier2の議事録（委任の内容）、実行計画 |
| 担当 | IT投資委員会事務局 |
| 期限 | [運用基準](../rules/03-standard.docx) 第13条 |
| 出力 | 委任記録の行、承認会議（ローカル）と起案者への通知、承認会議（ローカル）の承認・否認の結果 |

**作業**

1. [決裁権限表](../rules/04-delegation-of-authority.xlsx)「委任記録」に、委任先・委任の範囲・条件・報告期限を登録する（[運用基準](../rules/03-standard.docx) 第12条）。
2. 承認会議（ローカル）に、委任の内容と実行計画を渡す。
3. 起案者に、承認会議（ローカル）で承認・否認を決めることを通知する。
4. 案件台帳に、承認会議（ローカル）に委ねたことを記録する。
5. 承認会議（ローカル）から承認・否認の結果を受け取ったら、委任記録の状態を更新し、§3.10 に進む。結果の報告の方法は（TBD: 承認会議（ローカル）に委ねた案件の報告と事後のモニタリング）とする。

**例外**: 結果が報告期限までに届かない → §4

## 4. 例外対応

| 状況 | 一次対応 | エスカレーション先 | 詳細 |
|---|---|---|---|
| 年次の受付期間を過ぎてIntakeFormが提出された | 受付を保留し、事務局の責任者に報告する | ポートフォリオ・IT投資チームの管理職 | （TBD: 締切を過ぎた提出の扱い） |
| 付議先（Tier1かTier2か）の判定が分かれる | 起案者に金額の内訳を確認する | ポートフォリオ・IT投資チームの管理職 | [運用基準](../rules/03-standard.docx) 第6条 |
| 優先順位の付いていない案件の実行計画が提出された | 受付を保留し、起案者にIntakeFormの提出（§3.5）を案内する | ポートフォリオ・IT投資チームの管理職 | [運用基準](../rules/03-standard.docx) 第5条 |
| 年次の会議の日程が変わった | 起案者に、変更した日程を周知し直す | ポートフォリオ・IT投資チームの管理職 | §3.1 |
| 議長が議題・開催日を確定しない／会議が定足数に達しない | 議長に開催日の変更を相談する | 各会議体の議長 | [憲章](../rules/02-charter.docx) 別表1・別表2 |
| Tier3の推奨案が期限までに届かない | Tier3の主催者に状況を確認する | Tier2の議長 | [運用基準](../rules/03-standard.docx) 第13条 |
| 承認会議（ローカル）の承認・否認の結果が報告期限までに届かない | 承認会議（ローカル）に状況を確認する | Tier2の議長 | （TBD: 承認会議（ローカル）に委ねた案件の報告と事後のモニタリング） |
| 起案者が決定に異議を出した | 異議の内容を記録し、議長に伝える | 各会議体の議長 | （TBD: 上申と差し戻しの手続き） |
| 起案者が、付議先の会議体の構成員である | 議長に伝える | 各会議体の議長 | [憲章](../rules/02-charter.docx) 第10条 |
