# 競争調達フレームワーク

当社IT調達における随意契約80%の構造を、非対称情報の経済学を土台に診断し、競争調達方式の導入を制度として設計するプロジェクトです。

## 本プロジェクトが伝えようとしていること

> 我々は発注の8割について、良い取引かどうかを知る手段を持っていない。
> これは交渉の問題ではないので、交渉では直らない。
> 直すには、比較対象を作る制度と、それを所有する主体が要る。

**提起することは一つです。** 調達方式の判定には第3の軸「競争適合性」が要る。そして、その判定と評価プロセスの完全性を所有する主体が要る。

## 本プロジェクトが扱わないこと

- **金額・効果試算・投資指標**。予算や体制の決裁を扱う文書ではありません。扱うのは制度の設計 ── 何を判定し、誰が何を所有するか ── に限ります。
- **随意契約の比率目標**（8割→X割）。判定を回せば、比率は結果として動きます。数値目標は形だけの入札を生みます。

競争方式の導入は**コスト削減施策ではなく、価格と品質を検証可能にするための情報収集機構**です。目的をコスト削減だと宣言すれば、競争は必ず「値切り交渉の別名」に変質します。

## 閲覧方法

`index.html` をブラウザで開いてください。00→03の順に読む構成です。日英切替に対応しています。

## 想定問答（appendix）

本文（00〜03）には主張のみを置き、**反論への備えはすべて `appendix/Anticipated_Questions.md` に集めています。** 防御が主張と同じ強さで本文に並ぶと、聞き手は主張を取り出せなくなるためです。

| 章 | 内容 |
|---|---|
| 1 | 提言そのものへの問い（随契を禁じるのか／数値目標／コスト削減ではない理由／なぜ新機能か） |
| 2 | 判定への問い（Sole/Single の分離、理由A〜C、前年比を認めない理由、初年度の正直な前提、三分岐） |
| 3 | 仕様記述への問い（閾値の置き方、項目2と項目6、手段ではなく結果で書く） |
| 4 | 競争プロセスへの問い（事前凍結、最低価格入札、応札市場の維持、契約標準条項） |
| 5 | **この提言でも解けないもの**（成立条件C1〜C8との照合、既存ロックイン） |
| 6 | 判定の運用規律、類型別ロックイン防止条項、制度が可視化するもの |

## 編集上の規律

- **本文に防御を戻さない。** 反論への備えが必要になったら、想定問答に足してください。
- **本文に金額・投資指標を持ち込まない。** 決裁を要する検討が必要になった場合は、独立した文書として起案してください（`_archive/` の旧素材を参照）。
- **様式1・2は HTML 版が正本です。** Markdown の原稿は二重管理になるため持ちません。
