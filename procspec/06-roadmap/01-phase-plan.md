## 3. フェーズ詳細

### P0 立上げ・設計（80人日）

**目的**: 何を・なぜ・どう作るかを確定させ、実装の入力を揃える。

**完了判定基準** `[推定]`

- [ ] 様式2 の全セクション定義を入手し、スコープを確定した
- [ ] **非機能要件の数値目標を確定した** ← 現在未達
- [ ] **規制対象の該当有無を確定した** ← 現在未達
- [ ] 権限マトリクスを業務側と合意した ← 現在未達
- [ ] 状態遷移（所属長承認の位置づけ含む）を確定した ← 現在未達

## 4. 依存関係とクリティカルパス

```
[非機能要件の定義] ──────────→ 3.7 性能・脆弱性診断 ──→ リリース
                                         ↑
[実IdP接続情報] ──→ 1.2 認証本実装 ──────┘
                          ↑
                    (所有者チェックは先行可能)

[様式14セクション定義] ──→ B/C のセクション追加

[ベースライン実測] ──────→ 3.8 UAT ──→ 効果測定
```

**クリティカルパス上の外部依存** `[推定]`

| 依存事項 | 遅延した場合の影響 | 回避策 |
|---|---|---|
| **実IdP接続情報** | 1.2 が完了せず、リリース不可 | **所有者チェック・ロール判定は先行実装できる** |
| **非機能要件の数値** | 3.7 に着手できない | 業務側との合意を最優先で進める |
| **ベースライン実測** | UAT の効果測定ができない | **今すぐ現行運用で計測を開始する** |
| クラウド環境 | ステージング・本番が作れない | ローカル PostgreSQL で差分を先に潰す |
