## 2. 環境構成

| 環境 | 用途 | 状態 |
|---|---|:--:|
| 開発 | ローカル（SQLite・仮認証） | ● 存在する |
| **ステージング** | 本番同等の検証 | **❌ 存在しない** |
| **本番** | 運用 | **❌ 存在しない** |

**環境差分と、その影響** `[実装]`

| 差分 | 本番移行時に顕在化しうる問題 | 検証方法 |
|---|---|---|
| SQLite → PostgreSQL | JSON型の扱い、トランザクション分離、同時実行時の楽観ロック挙動、性能特性 | ステージングで実測 |
| 仮認証 → OIDC | トークン検証、セッション、ロールのクレーム取得 | 実IdP接続後に検証 |
| CORS 全許可 → 限定 | プリフライト、クレデンシャル送信 | ステージングで検証 |

> **3つの差分が同時に顕在化するのが最も危険** `[推定]`。ステージング環境の整備で段階的に潰すべき。
> → [ADR-0004](../02-architecture/05-adr/0004-sqlite-for-development.md)、[バックログ](../06-roadmap/02-backlog.md)

| 項目 | 状態 |
|---|---|
| 移行対象 | **未定** `[未確認]` |
| 移行元 | 現行運用（Excel/紙）と推測されるが不明 `[推定]` |
| 見積上の扱い | **「既存データの大規模クレンジング」は除外事項** `[資料]` |

> **移行の有無自体が不明** `[未確認]`。除外事項に「大規模クレンジング」とあるため、**何らかの移行は想定されている可能性がある** `[推定]`。
>
> ⚠️ **移行がある場合、アプリの設計に影響する**（旧データを受け入れる項目、移行期間中の並行運用）。
> **リリース直前ではなく、今の段階で確認すべき事項。**

**開発DB → 本番DB の移行**（データ移行とは別問題）`[実装]`

| # | 作業 |
|---|---|
| 1 | `schema.prisma` の provider を `postgresql` に変更 |
| 2 | `CaseAnswer.data` を `String` → `Json` に変更 |
| 3 | **アプリ側の `JSON.parse`/`stringify` を全て除去**（`CasesService.toDto`、`DraftsService.patch`） |
| 4 | `DATABASE_URL` を差し替え、マイグレーションを作り直す |
| 5 | 開発データの扱いを決める（破棄が妥当 `[推定]`） |

> **3 が見落とされやすい。** `schema.prisma` のコメントは 1・4 のみ言及している `[実装]`。**移行手順書は存在しない。**
