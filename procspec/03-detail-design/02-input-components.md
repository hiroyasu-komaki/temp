# 入力部品仕様

- **出典**: 設計助言 §2-2 `[資料]` / 実装の棚卸し `[実装]`
- **最終更新**: 2026-07-25

---

## 1. 部品化の判断基準

**原則: 定型・半定型は部品化し、本質的に自由な記述だけを textarea に残す** `[資料]`（助言 §2-2）。

| 自由記述に残す | 構造化する |
|---|---|
| 目的・背景、要求事項など本質的に文章の内容 | 数値（性能値・稼働率・金額・年数） |
| 例外的・非定型な補足（`nf_note`, `s5_text`） | 日付（RFP期限・稼働希望日） |
| | 選択肢が列挙できるもの（契約類型） |
| | 繰り返し構造（SLA行・評価配点行） |
| | 条件付きで詳細を聞くもの（非機能のチェック→値入力） |

## 2. 実装されている入力パターン ★

> **現在3種類のパターンが存在する** `[実装]`。**この3つが、拡張時の設計単位になる。**

### パターン1: 自由記述（`FreeTextStep`）

- 単一の textarea＋ガイド文
- 適用: セクション1・2・3
- **汎用化されている唯一のパターン** — `FreeTextStep` は複数ステップで再利用されている `[実装]`

### パターン2: チェック → 条件付き詳細入力（`Step4Fields`）

- チェックボックスで該当を選び、該当したものだけ数値/選択入力を展開
- 適用: セクション4（非機能要件）
- **助言が特に推奨したパターン** `[資料]`:「該当項目だけ数値/選択入力に。自由記述は『補足』欄に降格」

| チェック | 展開される入力 |
|---|---|
| `ck_perf` 性能 | `nf_perf` 応答秒数 / `nf_perf_u` 同時利用者数 |
| `ck_avail` 可用性 | `nf_avail` 稼働率% / `nf_rto` RTO / `nf_rpo` RPO |
| `ck_sec` セキュリティ | `nf_sso` SSO要否 / `nf_log` ログ保管年数 |
| `ck_reg` 規制 | `reg_gxp` / `reg_pi` / `reg_sox` |

### パターン3: 行テーブル（`StepSlaFields` / `Step11Fields`）

- 行の追加・削除ができる表形式
- 適用: セクション4-2（SLA）、11（評価配点）
- **既に2箇所で使われているが、共通部品化されていない** `[実装]` — それぞれ独立に実装されている

| 用途 | 列 | 追加機能 |
|---|---|---|
| SLA | 指標／目標値／測定方法／未達措置（すべて text） | — |
| 評価配点 | 評価項目／配点(number)／評価観点 | **合計100の自動チェック** |

> ⚠️ **パターン3が2箇所で重複実装されている。** 汎用化の最有力候補 `[推定]`。
> → [拡張性への配慮 §4-1](../02-architecture/04-extensibility.md)

### パターン外: 個別実装（`Step0Fields` / `Step5Fields`）

- セクション0（案件情報・類型）: テキスト＋類型選択カード
- セクション5（制約・予算）: 費目テーブル（自動合計）＋日付ピッカー×2＋textarea

## 3. セクション別の入力仕様

### セクション 0: 案件情報・類型

| 項目 | ラベル | 部品 | 必須 | 備考 |
|---|---|---|:--:|---|
| `title` | 件名 | text | ✅（作成時のみ） | |
| `period` | 契約期間 | **text** | − | ⚠️ **日付化されていない**（→ §5） |
| `primary` | 契約類型 | 選択カード | − | `CONTRACT_TYPES` から。選択でステップが絞り込まれる |

### セクション 4: 非機能要件

パターン2。詳細は §2 の表。自由記述は `nf_note`（補足）に降格済み `[実装]` — **助言の意図どおり** `[資料]`。

### セクション 4-2: SLA

パターン3。行の追加（`addrow`）・削除（`xrow`）が可能 `[実装]`。

### セクション 5: 制約・予算

| 項目 | 部品 | 自動計算 |
|---|---|---|
| `b_init` / `b_run` / `b_lic` | number | **合計を自動表示**（`toLocaleString("ja-JP")` で3桁区切り） |
| `d_rfp` / `d_go` | **date ピッカー** ✅ | — |
| `s5_text` | textarea | — |

**自動計算** `[実装]`

| 対象 | 式 | 丸め | 表示 |
|---|---|---|---|
| 予算合計 | `b_init + b_run + b_lic` | なし（整数前提） | `￥ 1,234,567` |

> 「電卓・手打ち集計が不要」というガイド文が表示される `[実装]` — **助言の意図が UI に反映されている良い例** `[資料]`。

### セクション 11: 評価項目と配点

パターン3＋自動チェック。

| 対象 | 式 | 判定 | 表示 |
|---|---|---|---|
| 配点合計 | `Σ weight` | `=== 100` | `合計：85 / 100（100になっていません）` ／ `合計：100 / 100 ✓ 適正` |

**既定4行** `[実装]`: 技術・実現性 40 ／ コスト 30 ／ 体制・実績 20 ／ 提案の具体性 10

> ⚠️ **この既定配点が組織の標準かは未確認** `[未確認]`。調達の公平性に直結するため、業務側の確認が必要。
> ガイド文に「VMO承認で凍結されます（凍結制御はプランB以降）」と明記されている `[実装]`。

## 4. ガイド文・入力例の見せ方

| 種別 | 置き場所 | 表示方式 | 実装 |
|---|---|---|:--:|
| ステップの目的説明 | ステップ冒頭 | 常時表示・1〜2行（`STEP_DEFS.purposeJa`） | ● |
| 項目の補足 | 項目直下 | 常時表示・短文（`hint`） | ● |
| **記入例** | — | **トグル / サイドパネル** | **○ 未実装** |
| プレースホルダ | 入力欄内 | 短い形式ヒント | ◐ |

> ⚠️ **記入例のトグル表示が未実装** `[実装]`。
> 助言 §2-2 は「プレースホルダの長い例文は良いガイドだが、入力欄に常時見えていると圧迫感がある。例文は『例を見る』トグルや脇のガイドパネルに寄せ、入力欄自体は軽く見せる」としている `[資料]`。
> → [バックログ](../06-roadmap/02-backlog.md)

## 8. 拡張時の指針

> **新しいセクションを追加するとき、まず既存3パターンで表現できないか検討する。** `[推定]`
> パターンを増やすほど、汎用化（[拡張性への配慮 §4-1](../02-architecture/04-extensibility.md)）のコストが上がる。

| 追加したい入力 | 使うパターン |
|---|---|
| 文章を書かせる | パターン1（`FreeTextStep`）— 既に汎用化済み |
| 該当する項目だけ詳細を聞く | パターン2 |
| 繰り返し構造 | パターン3 |
| 上記で表現できない | **まず [ADR](../02-architecture/05-adr/) で判断を記録してから実装する** |
