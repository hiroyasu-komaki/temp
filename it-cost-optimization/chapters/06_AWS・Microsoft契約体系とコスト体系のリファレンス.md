# 6. AWS・Microsoft　契約体系とコスト体系のリファレンス

> **この章の位置づけ**：一般消費者向け契約・無料枠を除き、企業のIT組織におけるベンダーマネジメント担当として押さえておくべきAWS・Microsoftの契約体系・コスト体系を整理するリファレンス章。
> **対象読者**：ベンダーマネジメント担当／調達部門

## 要旨

以下は、企業のIT組織におけるベンダーマネジメント担当として押さえておくべき契約体系・コスト体系を整理したものである。AWSの基本思想は「オンデマンド課金がデフォルトであり、そこからいかにコミットメントによって値引きを引き出すか」という一本の軸に集約される。一方Microsoftの構造はAWSより複雑で、「どの契約ビークルを結ぶか」「Azureの消費コミットをどう設計するか」「サポートをどう契約するか」という3層が別々の交渉軸として存在し、かつ相互に連動する。「基準点とタイミングをベンダーに握らせない」という原則は、実務上、AWS・Microsoftそれぞれの具体的な条項に集約される。

## 6.1 AWS

AWSの基本思想は「オンデマンド課金がデフォルトであり、そこからいかにコミットメントによって値引きを引き出すか」という一本の軸に集約される。

| 契約種類 | 期間 | 対象製品・サービス | 値引率・インセンティブ |
|---|---|---|---|
| AWS Organizations / Consolidated Billing | 定めなし(継続的な管理の枠組み) | 全AWSサービス(複数アカウントの統合) | 直接の値引きではなく、ボリュームディスカウント・コミット割引を複数アカウントで合算するための基盤 |
| Reserved Instances (Standard) | 1年/3年 | EC2等、特定インスタンスタイプ・リージョン | 最大約72%引(構成変更不可・最も硬直的) |
| Reserved Instances (Convertible) | 1年/3年 | EC2、インスタンスファミリー変更可 | Standardよりやや低い割引率 |
| Savings Plans (Compute) | 1年/3年 | EC2/Fargate/Lambda等サービス横断 | 最大約66%引(柔軟性が高い) |
| Savings Plans (EC2 Instance) | 1年/3年 | 特定インスタンスファミリー | RIに近い割引率 |
| EDP/PPA | 通常1〜3年(大口は複数年) | 年間総支出額(クロスサービス/サービス別) | 個別交渉ベース(規模により数%〜20%超) |
| MAP (Migration Acceleration Program) | フェーズ単位(対象期間12〜24か月) | 移行対象ワークロードの初年度支出(要タグ付け) | Assess約5%/Mobilize約20%/Migrate15〜25%相当の資金・クレジット |
| サポート契約(Business Support+/Enterprise Support/Unified Operations) | 定めなし(継続) | AWS利用額全体 | 利用額に対する逓減型%課金(最低月額あり。値引きではなく費用体系) |

**土台：AWS Organizations + Consolidated Billing**　複数のAWSアカウントを一つの支払いアカウント配下に統合する仕組み。これ自体はコストそのものではないが、ボリュームディスカウントの合算や、Reserved Instances／Savings Plansの割引を組織内の複数アカウントで共有できるかどうかを決める土台であり、これが整理されていないと、良い契約条件を取っても割引効果が社内で分散してしまう。ベンダーマネジメント上、最初に確認すべき前提条件である。

**コミットメント型の割引契約**　Reserved Instances(Standard：特定インスタンスタイプ・リージョン固定、1年/3年、割引率は最大級だが最も硬直的／Convertible：インスタンスファミリー変更可、Standardより割引率は下がる)、Savings Plans(Compute：時間あたりドル額のコミット、サービス横断で柔軟に適用／EC2 Instance：特定インスタンスファミリー限定、RIに近い割引率)、EDP(Enterprise Discount Program)・PPA(Private Pricing Agreement：年間総支出額を基準とした個別交渉ベースの割引。現在この2つは実務上ほぼ同一の仕組みに収斂しており、AWS自身も「クロスサービス割引」「サービス別割引」という呼び方への整理を進めている段階)。

**サポート契約**　Business Support+(最低月額$29、AWS利用額に対し9％〈〜$10K〉→7％〈〜$80K〉→5％〈〜$250K〉→3％〈$250K超〉)、Enterprise Support(最低月額$5,000、10％〈〜$150K〉→7％〈〜$500K〉→5％〈〜$1M〉→3％〈$1M超〉)、Unified Operations(最低月額$50,000、10％〈〜$1M〉→6％〈〜$5M〉→5％〈$5M超〉)。サポート費用は利用額に自動連動する「隠れた変動費」であり、EDP/PPA交渉の際はサポート費用込みの実質単価で比較する必要がある。

**AWS Marketplace**　サードパーティソフトウェアの調達チャネルで、Private Offer経由の購入がEDP/PPAのコミット消化に充当できる場合がある。ソフトウェア調達をMarketplace経由に寄せることで、単一の契約枠内でコミット消化と調達効率化を同時に図れる余地がある。

## 6.2 Microsoft

Microsoftの構造はAWSより複雑で、「どの契約ビークルを結ぶか」「Azureの消費コミットをどう設計するか」「サポートをどう契約するか」という3層が別々の交渉軸として存在し、かつ相互に連動する。

| 契約種類 | 期間 | 対象製品・サービス | 値引率・インセンティブ |
|---|---|---|---|
| EA (Enterprise Agreement) | 3年(年次更新) | M365/Windows/EMS等ユーザーライセンス全般(事実上6,000ユーザー以上が対象) | レベル帯による交渉制割引(規模により概ね15〜40%) |
| MCA-E (Microsoft Customer Agreement for Enterprise) | 3年(月次消費課金) | EA対象外・下位帯顧客向け全製品 | list価格からの個別交渉ディスカウント(概ね5〜20%) |
| CSP + NCE | 月次/年次(シート単位) | 中堅規模向け全製品(リセラー経由) | リセラーとの個別条件(年間コミットしたシート数は契約期間中削減不可) |
| MACC (Azure Consumption Commitment) | 通常EA/MCA-Eと同じ3年 | Azure消費額 | 割引そのものではなく、予約割引・個別割引への「アクセス資格」 |
| Unified Support | 定めなし(通常EA等と合わせて更新) | Microsoft全体支出額(オンプレ含む) | Core/Advanced/Performanceの3階層(総支出額の概ね6〜12%) |
| Software Assurance (SA) | EA契約期間に連動 | 対象ライセンスのアップグレード権・保守権 | 割引ではなく権利(新バージョンへの無償アップグレード等) |

**契約ビークル**　EA(Enterprise Agreement：3年、年次更新〈アニバーサリー〉、ユーザー数に応じたレベル帯による割引〈交渉制〉、年次true-up〈増加分のみ反映、true-downなし〉。下位レベル帯〈旧Level A/B〉は既に廃止され、事実上の下限は6,000ユーザー規模まで引き上げられている)、MCA-E(Microsoft Customer Agreement for Enterprise：3年、月次消費ベース課金、list価格からの個別交渉ディスカウント〈概ね5〜20％〉、true-upの概念自体がなく月次消費で自動反映。下位レベル帯から外れた顧客の受け皿としてMicrosoftが積極的に誘導している)、CSP+NCE(Cloud Solution Provider＋New Commerce Experience：リセラー経由、月次/年次のシート契約、年間コミットしたシート数は契約期間中の削減不可)。

**MACC(Microsoft Azure Consumption Commitment)**　EAまたはMCA-Eの中に組み込まれる、Azure消費額に関する別枠のコミット。MACCそのものは割引ではなく、Reserved Instances相当の予約割引やEAレベルの個別割引にアクセスするための「資格」という位置づけである点が最も誤解されやすい。期間は通常EA/MCA-Eと同じ3年。消費不足が生じた場合は契約終了時に未消化分の支払い義務が発生し(標準では減額調整なし、交渉次第で1〜3割程度の見直し余地)、コミットを超過した分はあらかじめ超過時の単価を交渉していないとオンデマンド料金に戻り、コミット単価より3〜5割程度割高になるリスクがある。Microsoft側の営業は見込み消費額の上限に近い水準でのコミットを提案してくる傾向があるため、見込みの下限に1〜1.5割のバッファを乗せた保守的な水準で設計するのが定石である。

**サポート契約：Unified Support**　Core(最低年額$25,000、Office/クライアント系6％・Azure/Dynamics系8％)、Advanced(最低年額$50,000、8％・10％)、Performance(最低年額$175,000、10％・12％)の3階層。実際の請求額は「最低年額」と「総支出額に対する料率計算」のいずれか高い方が適用される。Azure/Dynamics系の料率がOffice系より高く設定されているため、AzureのAI関連支出が増えるほどサポート費用が加速度的に増加する構造になっている点に注意が必要である。

**Software Assurance(SA)**　旧来のEAに含まれてきた、アップグレード権・保守権に相当する要素。EAの相対的な重要性が下がっていく中で新規契約における比重は下がりつつあるが、既存EA契約の内容を理解する上では引き続き必要な知識である。

## 6.3 基準点とタイミングの所在

「基準点とタイミングをベンダーに握らせない」という原則は、実務上、AWSにおいてはEDP/PPAのコミット額算定基準となる利用量の測定期間、Microsoftにおいては①EA更新時にどのレベル帯に位置づけられるか、②MACCのコミット水準とその算定根拠となる消費実績、③Unified Supportの料率計算のベースとなる総支出額、の3点に集約される。次回交渉に向けて準備すべきデータは「現在の利用実績」だけでなく「最適化後にあり得る利用水準の試算」であり、これを持たずに交渉に入ると、いずれの契約体系においても現状の(最適化前の)水準がそのまま基準点として固定されてしまう。

## この章の結論

- AWSの契約体系は「オンデマンド課金がデフォルト、そこからコミットメントで値引きを引き出す」という単純な一本軸であり、RI/Savings Plans/EDP・PPA/MAP/サポート契約が主要な要素となる。
- Microsoftの契約体系は「契約ビークル(EA/MCA-E/CSP+NCE)」「Azure消費コミット(MACC)」「サポート契約(Unified Support)」の3層が相互連動する、より複雑な構造である。
- 「基準点とタイミングをベンダーに握らせない」という原則は、AWSではEDP/PPAの利用量測定期間、MicrosoftではEAレベル帯・MACC水準・Unified Support料率算定基準の3点に集約される。
