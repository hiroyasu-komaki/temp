# README：VMOベンダーマネジメント資料

## 概要

このフォルダには、企業IT組織におけるVMO（Vendor Management Office）の定義・導入・役割・予算起点の働きかけをまとめた本編、独立した参照用の付録、および年度ごとの作業用フォルダが含まれています。

VMOに関する規定とRunbookは、今後別途整備します。本編の第3章は、それらの前提となる役割と実務の概要だけを扱います。

## 各文書の概要

### 本編（chapters/）

| 章 | 想定読者 | 内容 |
|---|---|---|
| [第1章 VMOの定義](chapters/01_definition.md) | IT組織の全メンバー | VMOとは何か。担う仕事と担わない仕事、ITのライフサイクルとの関わり（4フェーズ・11の相談の入口）、VMOが作り守る情報とベンダーのTier、他のIT機能との役割と責任（RACI）、ステークホルダーへの提供価値、委託取引に関わる法令・規制と場面ごとの分担 |
| [第2章 VMOの導入](chapters/02_introduction.md) | CIO・IT管理職 | VMOをどう置き、育てるか。提供方法の選択（3モデルの比較とエージェント型を選ぶ理由）、目指す水準、人材（L1の成長段階）、立ち上げの進め方、導入後のモニタリング |
| [第3章 VMOの役割](chapters/03_roles.md) | VMO担当者、相談者 | 誰が何を担い、相談にどう応じるか。4つの役割とVMO管理者、相談を受けるときの共通の型、基盤業務、相談の入口ごとの対応（典型的なケースとVMOのアプローチ） |
| [第4章 予算起点の働きかけ](chapters/04_budget-driven-activity.md) | VMO担当者、IT担当者、調達部門 | 具体的に何をするか。来年度予算を起点にした働きかけ。依存度と実行シグナル（Green／Yellow／Red）、依存の型、4つの目標指標、新規案件の分岐とベンダー集計からの6ステップ |

本編全体を通じて、次の考え方をとります。

- VMOは依頼部門の代理人として動く「エージェント型」であり、個別案件の意思決定の最終責任は常に依頼部門にある
- 取適法・労働者派遣法・GxPなど法令上の義務を負い、発注・検収・委託先の評価を行う主体は依頼部門であり、VMOは契約条件の設計・点検と記録の維持で支援する

### 付録（appendix/）

各付録は本編を参照しない、独立したリファレンス文書として構成しています。

- **付録A**：相談受付テンプレート集 ― 相談の切り分けと、相談種別ごとの情報提供依頼テンプレート
- **付録B**：実務様式集 ― ベンダー台帳項目定義、評価基準表、提案比較表、月次レビューアジェンダ、年次評価、オンボーディング／オフボーディングのチェックリスト
- **付録C**：サポート運用体制モデルの比較 ― Follow-the-sun／24-365／通常営業の3モデルの選定基準
- **付録D**：SOWとSLA ― 運用保守委託における契約文書の構造、SOW・SLAそれぞれの設計と点検チェックリスト
- **付録E**：データ保護・セキュリティの契約要件 ― クラウド/SaaSにおける責任分界、契約に定めるべき事項、点検チェックリスト

## 正本と更新のルール

- 本文の正本は `chapters/` の Markdown。第2章の図版（`images/02_model-*.png`）は `src/three_models_chart.py` で生成したもので、式やパラメータを変えるときはスクリプトと第2章 2.11節を同時に更新し、スクリプトを実行して画像を作り直す
- `plans/` は年度ごとの作業用で、正本ではない。進め方を変えるときは第4章を先に更新する
- HTML版は持たない
