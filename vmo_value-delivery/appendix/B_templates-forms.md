# 付録B：実務様式集（台帳・評価・比較・レビュー・契約開始/終了）

## B.1 本付録の位置づけと使い方

本付録に収めるのは、**VMO自身が作成・記入する様式**である。相談者に記入を依頼するテンプレート（相談の切り分け、情報提供依頼）は付録Aに分けている。相談を受けた瞬間に開くのが付録A、案件が動き出してから開くのが本付録である。

| 節 | 内容 | 使う場面 |
|---|---|---|
| B.2 | ベンダー台帳の項目定義 | 平時の維持、契約締結時の登録 |
| B.3 | 評価基準表（RFP／見積比較） | 提案を受け取る**前**に作成する |
| B.4 | 提案比較表 | 提案受領後の評価 |
| B.5 | 月次レビューのアジェンダ | 稼働後の定例 |
| B.6 | 年次評価の観点 | 契約更新の判断材料 |
| B.7 | 契約開始・終了時のチェックリスト | オンボーディング／オフボーディング |

## B.2 ベンダー台帳の項目定義

| 項目 | 内容 | 必須 |
|---|---|---|
| ベンダーID | 一意の識別子 | ○ |
| ベンダー名 | 正式名称 | ○ |
| 分類 | 戦略／重要／一般 | ○ |
| 対象システム・サービス | 複数ある場合は列挙 | ○ |
| 契約種別 | 保守／ライセンス／クラウド／SES／その他 | ○ |
| 契約金額 | 年額。従量課金がある場合は固定分と変動分を分ける | ○ |
| 契約期間 | 開始日・満了日 | ○ |
| **更新方式** | 自動更新／都度更新 | ○ |
| **解約通知期限** | 満了日の何日前か、および実際の期限日 | ○ |
| 自社側の業務窓口／技術窓口 | 氏名・所属 | ○ |
| ベンダー側の窓口 | 氏名・連絡先 | ○ |
| リスク評価 | 評価結果と評価日 | ○ |
| 次回レビュー予定日 | 分類に応じた頻度で設定 | ○ |
| 契約書の保管場所 | 原本・電子の所在 | ○ |
| 再委託先 | 開示を受けている範囲 | 該当時 |

## B.3 評価基準表（RFP／見積比較）

**配布前に確定させ、相談者と合意しておく。** 提案受領後に基準を決めると、選定の正当性が失われる。

| 評価項目 | 配点 | 評価基準（何点をどう付けるか） | 評価者 |
|---|---|---|---|
| 機能適合度 | 　 | 必須要件の充足率で機械的に算出 | |
| 実績・信頼性 | 　 | 同規模・同業種での導入実績数 | |
| セキュリティ | 　 | 認証の取得状況、第三者保証報告書の有無 | |
| サポート体制 | 　 | 提供時間、体制、エスカレーション経路の明確さ | |
| 価格 | 　 | 契約期間中の総額（初期＋運用＋想定される追加費用） | |
| 将来性・拡張性 | 　 | ロードマップ、API提供、他システム連携 | |
| **合計** | **100** | | |

> 配点は案件ごとに変える。「2社が同点だったとき何で決めるか」の答えに最も高い配点を置く。

## B.5 月次レビューのアジェンダ

```markdown
# ベンダー月次レビュー
日時：
ベンダー：
参加者：

1. 前月のサービスレベル実績
   - 項目ごとの目標値と実績、達成／未達の別
   - 未達がある場合、原因と対応

2. インシデントの振り返り
   - 発生件数（優先度別）
   - 重大インシデントの経緯、原因、再発防止策の進捗

3. 継続課題の進捗
   - 前回までに合意した改善事項の状況

4. 当月の予定
   - 計画作業、リリース、メンテナンス

5. 依頼・相談事項
   - 自社からベンダーへ
   - ベンダーから自社へ

6. 次回までのアクション
   - 内容、担当、期限
```

## B.6 年次評価の観点

点数化する場合は、配点と評価基準を評価期間の開始前に決めておく。

| 観点 | 見るもの | データの出どころ |
|---|---|---|
| サービス品質 | サービスレベルの達成率、重大インシデントの件数と内容 | 月次報告、インシデント記録 |
| 対応の質 | 一次応答の速さ、報告の分かりやすさ、改善要求への反応 | 利用部門への確認 |
| コスト | 契約額と実支払額の差、追加費用の発生状況 | 支払実績 |
| 契約遵守 | SOW記載業務の実施状況、成果物の提出状況 | 成果物の受領記録 |
| リスク | 体制変更、要員交代、財務状況、セキュリティ事案 | ベンダーからの報告、公開情報 |
| **次年度の方針** | 継続／条件見直し／切替検討 | 上記を踏まえた判断 |

## B.7 契約開始・終了時のチェックリスト

### B.7.1 オンボーディング（契約締結後30日）

**契約情報の登録**

- [ ] ベンダー台帳に登録（B.2の項目）
- [ ] **解約通知期限をカレンダーに登録**（自動更新の場合は必須）
- [ ] 契約書の保管場所を記録
- [ ] 支払条件（支払サイト、前払／後払、請求単位）を登録

**体制の確立**

- [ ] 自社側の業務窓口・技術窓口を任命
- [ ] ベンダー側の窓口と連絡先を取得
- [ ] エスカレーション経路を設定（技術的な引き継ぎ先と、管理者への報告経路の両方）
- [ ] 定例レビューの頻度・参加者・形式を合意

**アクセスの設定**

- [ ] アカウント発行と、付与権限が業務範囲に対して最小か確認
- [ ] ネットワーク・VPN設定
- [ ] **発行したアカウントの一覧を記録**（終了時に遮断する対象）
- [ ] 秘密保持契約の締結状況を確認

**立ち上げ**

- [ ] キックオフ（双方の窓口、対応範囲、連絡手段の確認）
- [ ] サービスレベルの相互確認（測定方法、報告形式、提出期限まで合意）
- [ ] 運用ドキュメントの提出期限を合意
- [ ] 初回レビューの日程を確定

<br>

### B.7.2 オフボーディング（解約通知期限から逆算）

> **起点の決め方**：契約満了日ではなく、**解約通知期限**から逆算する。関連契約が複数ある場合、最も早い通知期限が全体の起点になる。通知期限を過ぎると、その時点で1更新期間分の契約が確定する。

**通知期限まで**

- [ ] 関連する契約をすべて棚卸し（保守、ライセンス、回線、監視、クラウド利用料）
- [ ] 各契約の解約通知期限を確認
- [ ] 中途解約の場合、違約金の有無と金額を確認
- [ ] 後継手段（後継ベンダー／内製化／廃止）を確定
- [ ] **解約通知を所定の方法・宛先で発行し、発行記録を残す**

**終了60日前**

- [ ] データ移管計画を完成（対象データ、形式、移管先、実施日）
- [ ] 残すべきデータと保存期間を確定（法令・監査要件を所管部門に確認）
- [ ] 引き渡しを受けるドキュメントの一覧を合意
- [ ] 並行稼働の要否と期間を確定
- [ ] 支払残高・**前払残高**を確認

**終了30日前**

- [ ] 運用ドキュメントを受領（運用手順書、設定情報、構成図）
- [ ] 既知の不具合・回避策の情報を受領
- [ ] アカウント一覧・権限一覧を受領
- [ ] 後継担当者への引き継ぎを実施
- [ ] データ抽出と、内容の検証

**契約終了日**

- [ ] データとドキュメントの受領完了を確認（**この確認前にアクセスを遮断しない**）
- [ ] 全アカウントの無効化、VPN・ネットワーク接続の遮断
- [ ] 貸与機器・入館証等の返却確認

**終了後14日以内**

- [ ] データ削除証明書の取得
- [ ] 最終精算（未払分の確定、**前払分の返還請求**、違約金の確認）

**終了後30日以内**

- [ ] 最終評価の実施（次回の選定に使う記録として残す）
- [ ] ベンダー台帳の更新（ステータス、終了日、終了理由）
- [ ] 事後検証（後継手段の稼働確認、移行漏れの有無）
- [ ] 案件記録の完成（所要期間、実費用、想定との差分）

<br>

### B.7.3 特に漏れやすい項目

| 項目 | 見落とした場合に起きること |
|---|---|
| 解約通知期限（複数契約のうち1つでも） | 1更新期間分の費用が丸ごと発生する |
| 前払費用の精算 | 返還請求できるものを取り漏らす |
| ドキュメント受領前のアクセス遮断 | 運用情報を取り返せなくなる |
| 周辺契約の棚卸し（回線、監視、ライセンス） | 主契約だけ解約し、周辺契約が残り続ける |
| データ削除証明の取得 | 監査時に削除を証明できない |
| 発行アカウント一覧の未把握 | 遮断漏れのアカウントが残る |
| 最終評価の記録 | 次回の選定で同じ失敗を繰り返す |
