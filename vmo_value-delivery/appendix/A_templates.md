# 付録A：相談受付テンプレート集（相談の切り分けと情報提供依頼）

## A.1 本付録の位置づけと使い方

相談は、たいてい曖昧な一言で始まる。「見積が高い気がする」「このベンダーでいいか見てほしい」「更新の時期なんだけど」。**その一言から実際の相談内容を推測し、必要な情報を相談者に言語化してもらうこと**が、最初の仕事になる。

本付録の中心は、そのための**情報提供依頼テンプレート**である。メール本文の文例ではなく、**相談の種類ごとに「何を書いてもらう必要があるか」**をまとめている。依頼メールを書くときは、A.3とA.4の該当項目をそのまま貼り付けて記入を依頼する。

| 節 | 内容 |
|---|---|
| A.2 | 相談の切り分け（曖昧な一言から、どの依頼テンプレートを使うか判断する） |
| A.3 | すべての相談に共通して依頼する項目 |
| A.4 | 相談の種類別 情報提供依頼テンプレート（11種） |

**本付録に収めるのは、相談者に記入してもらうものだけ**である。VMO自身が作成・記入する様式（ベンダー台帳の項目定義、評価基準表、提案比較表、レビューのアジェンダ、契約開始・終了時のチェックリスト）は付録Bに分けている。相談を受けた瞬間に開くのが本付録、案件が動き出してから開くのが付録Bである。

## A.2 相談の切り分け

### A.2.1 最初に確認する3つの質問

多くの相談は、次の3問で行き先が決まる。曖昧な一言を受けたら、まずこれを聞く。

| # | 質問 | 分岐の効き方 |
|---|------|-------------|
| 1 | **現行契約はありますか** | ない＝新規（A.4.1〜A.4.4）／ある＝既存（A.4.5〜A.4.11） |
| 2 | **いまどの段階ですか**（未着手／候補あり／内示済み／契約済み） | 段階によって打てる手が変わる。内示済みなら選定の議論はできない |
| 3 | **いつまでに決める必要がありますか** | 逆算して実行可能な選択肢が絞られる |

<br>

### A.2.2 相談者の言葉と、実際に必要なこと

| 相談者が言うこと | 実際に必要なこと | 使うテンプレート |
|---|---|---|
| 「いくらくらいかかるものですか」 | 相場の提示。まだ何も決まっていない | A.4.1 |
| 「見積が高い気がする」 | 現行契約なし＝相場との比較／あり＝値上げ検証 | A.4.1 または A.4.6 |
| 「ベンダーを選びたい」 | 競争環境をつくる準備 | A.4.2 |
| 「このベンダーでいいか見てほしい」 | 選定前＝A.4.2／内示済み＝A.4.3 | A.4.2 または A.4.3 |
| 「契約書を見てほしい」 | 締結前＝A.4.4／既存の整理＝A.4.8 | A.4.4 または A.4.8 |
| 「SLAって何を書けばいいの」 | 契約条件の設計 | A.4.4 |
| 「ベンダーの対応が遅い／雑だ」 | 事実の記録化と改善要求 | A.4.5 |
| 「値上げの連絡が来た」 | 妥当性の検証と交渉 | A.4.6 |
| 「来年いくら積めばいい」 | 予算根拠の作成 | A.4.7 |
| 「何の契約があるか分からない」 | 契約の棚卸し | A.4.8 |
| 「ライセンスが足りない／余っている」 | 契約数量と実態の差分是正 | A.4.9 |
| 「更新の時期なんだけど」 | 継続判断＝A.4.10／条件見直し＝A.4.9 | A.4.10 または A.4.9 |
| 「このベンダー、変えたほうがいい？」 | 継続と切替の比較 | A.4.10 |
| 「このシステム、来年やめます」 | 契約終了の段取り | A.4.11 |

> **判断に迷うとき**：相談者に「どちらの相談か」を聞かない。A.2.1の3問を聞けば、こちらで判断できる。相談者は自分の相談がどの類型かを知らない。

## A.3 すべての相談に共通して依頼する項目

A.4の各テンプレートを使う前に、必ずこの7項目の記入を依頼する。

| # | 記入を依頼する項目 | 記入の粒度 |
|---|---|---|
| 1 | 対象のシステム／サービス名と、利用している部門 | 正式名称と通称の両方。利用者数の概算 |
| 2 | いまどの段階か | 未着手／情報収集中／候補あり／内示済み／契約済み から選択 |
| 3 | 決めなければならない期限と、その根拠 | 日付と、なぜその日付なのか（予算年度、稼働希望日、契約満了 等） |
| 4 | 現行契約の有無 | ある場合はベンダー名、契約金額、契約期間、満了日 |
| 5 | 予算の状況 | 確保済み／これから確保／上限額 |
| 6 | **すでにベンダーに伝えている内容** | 予算額、時期、内示の有無、他社検討の事実を伝えているか |
| 7 | 最終的な決裁者 | 役職名。稟議の要否と想定所要日数 |

> **6番を必ず聞く。** 予算額を伝えている、内示を出している、他社を検討していないと伝えている——これらは価格交渉の余地をほぼ失わせる。後から判明すると、それまでの検討がやり直しになる。

## A.4 相談の種類別 情報提供依頼テンプレート

各テンプレートは、A.3の共通項目に**追加して**依頼する項目である。

### A.4.1 選択肢と相場を知りたい

**確定させたいこと**：どの類型の選択肢を、どの規模で検討するのか

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 解きたい業務課題 | 「製品が欲しい」ではなく、いま何に困っているか。現状の運用と、その問題点 |
| 必須要件と、あきらめてよい要件 | 箇条書きで分けて記入。**全部必須にすると選択肢が1つになり、価格が動かなくなる** |
| 利用規模 | 利用者数、拠点数、データ量、想定される増減 |
| 想定している導入時期 | 予算年度との関係 |
| 既存システムとの関係 | 置き換え／併用／連携。連携先システム名 |
| すでに見聞きしている製品・ベンダー | 名前と、どこで知ったか |

**添付を依頼するもの**：現状の業務フロー、既存システムの構成が分かる資料（あれば）

**回答が薄いときの追い方**：要件が「使いやすいこと」等の抽象語で埋まっている場合、「いまの運用でいちばん時間がかかっている作業は何か」を聞き直す。具体的な作業から要件を起こす。

<br>

### A.4.2 RFP・見積依頼の準備

**確定させたいこと**：評価の基準と、誰がどの観点で評価するのか

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 要件の一覧 | 文書があれば添付。なければ箇条書きで。**必須／任意の区別を付ける** |
| 評価に参加する人と所属 | 氏名・所属・評価する観点（機能／技術／運用／コスト） |
| 重視する観点の順位 | 機能適合、価格、実績、サポート体制、拡張性などの優先順位 |
| 候補ベンダーと、候補にした理由 | 社数と各社の名前。紹介・既存取引・Web検索などの経緯 |
| 現行契約の解約条件（代替探索の場合） | 満了日、解約通知期限、中途解約の可否 |
| スケジュールの制約 | 稼働希望日、予算年度、社内承認の所要期間 |
| 現行ベンダーに検討を知らせてよいか | 可／不可。不可の場合、資料の配布範囲を限定する |

**添付を依頼するもの**：要件定義書、現行システムの構成図、現行契約書、直近の利用実績データ

**回答が薄いときの追い方**：評価観点の優先順位が付けられない場合、「2社が同点だったとき、何で決めますか」と聞く。それが最優先の観点である。

<br>

### A.4.3 決まっている案件の契約前確認

**確定させたいこと**：交渉に使える余地がどれだけ残っているか

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| ベンダーにどこまで伝えたか | 内示の有無、予算額の開示、他社検討の有無を伝えたか、稼働日を約束したか |
| 見積の内訳 | 一式表記か、単価×数量が分かるか |
| 契約書ドラフトの有無 | ある場合、どちらの雛形か（自社／ベンダー） |
| 契約締結の予定日と稼働希望日 | 交渉に使える日数を算出する |
| 他社見積の有無 | 取得している場合は金額と社名 |
| そのベンダーに決めた理由 | 機能／実績／既存取引／担当者の印象 など |

**添付を依頼するもの**：見積書、提案書、契約書ドラフト、SOW・仕様書に相当する資料

**回答が薄いときの追い方**：「一式」見積しか無い場合、ベンダーに内訳の提出を求める。内訳が出せない見積は、交渉も検証もできない。

> **注意**：この相談は選定のやり直しを求めるものではない。条件の妥当性検証とリスクの洗い出しに限る。

<br>

### A.4.4 契約条件の設計

**確定させたいこと**：サービスレベルの目標値を決めるための前提

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 停止したときの事業影響 | 何分／何時間止まると、誰の、どの業務が止まるか |
| 許容できる停止時間 | 平日日中／夜間／休日それぞれについて |
| 業務のピーク時期・時間帯 | 月末、決算期、特定曜日など |
| 扱うデータの機密区分 | 個人情報・機微情報の有無、データの保管場所の制約 |
| 希望する契約期間と更新方式 | 単年／複数年、自動更新の可否 |
| 想定される利用の増減 | 契約期間中に数量が変わる見込み |
| 過去に困ったこと | 前任者・他システムで、契約条件が原因で困った経験 |

**添付を依頼するもの**：ベンダー提示のSOW（仕様書・業務範囲一覧）、SLA案、利用規約

**回答が薄いときの追い方**：「許容できる停止時間」を即答できないことが多い。「金曜の夜に止まって、月曜の朝まで直らなかったら困りますか」と具体的な場面で聞く。

<br>

### A.4.5 ベンダーの対応品質への不満

**確定させたいこと**：交渉の根拠になる事実

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 具体的な事象 | **3件以上**。それぞれ発生日時、依頼内容、実際の対応、どこが問題だったか |
| すでにベンダーへ伝えた内容 | 伝えた日、相手、伝え方（口頭／メール）、回答 |
| いつ頃から悪化したか | 担当者交代、体制変更、契約更新などの心当たり |
| 契約上の該当箇所 | SLA項目、SOWの業務一覧のどれに反するか（分かる範囲で） |
| 望む着地点 | 改善／減額／担当交代／契約見直し のどれか |

**添付を依頼するもの**：やり取りのメール、チケットの記録、SLA報告書（直近3〜6ヶ月分）

**回答が薄いときの追い方**：「対応が遅い」だけで具体例が出ない場合、直近のチケット一覧を出してもらい、そこから遅延の実績を抽出する。相談者に思い出させるより、記録から拾うほうが早い。

<br>

### A.4.6 値上げ要請への対応

**確定させたいこと**：値上げの根拠と、交渉に使える材料

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 値上げ幅 | 現行金額、提示金額、増加率。単価と数量の内訳 |
| 提示された根拠 | ベンダーの説明をそのまま（人件費上昇／為替／ライセンス改定／サービス拡充 など） |
| 通知を受けた日と、適用希望日 | 交渉に使える日数を算出する |
| 契約上の価格改定条項 | 合意が必要か、通知のみで足りるか、通知期限の定めがあるか |
| サービス内容の変更の有無 | 値上げとあわせて範囲が増減していないか |
| 同一ベンダーとの他の契約 | 分かる範囲で契約名と金額 |
| 切替の現実性 | 代替候補の有無、切替にかけられる期間 |

**添付を依頼するもの**：値上げ通知の原本、現行契約書（価格改定条項を含む）、直近の請求書

**回答が薄いときの追い方**：根拠が示されていない場合、それ自体が交渉材料になる。「根拠の提示を求める」ことを最初のアクションにする。

<br>

### A.4.7 来年度予算の積算

**確定させたいこと**：積算の対象範囲と、必要な精度

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 対象範囲 | どのシステム・どの契約まで含めるか。保守／ライセンス／回線／クラウド利用料の区別 |
| 現行の年間実績 | 契約額と、実際の支払額の両方 |
| 来年度の増減要因 | 利用者増、機能追加、値上げ通知、契約満了、システム廃止 |
| 予算提出の期限 | 日付。差し戻しがあり得るかどうか |
| 求められる精度 | 概算でよいか、確度の高い数字が必要か |
| 前年度に超過・余剰が出たか | 出た場合はその理由 |

**添付を依頼するもの**：現行契約の一覧、直近12ヶ月の請求実績、前年度の予算と実績の対比

**回答が薄いときの追い方**：現行実績が分からない場合、契約書ではなく**支払実績データ**から入る。実態は請求書にしか現れないことが多い。

<br>

### A.4.8 契約の棚卸し

**確定させたいこと**：どこまでを対象にし、何をもって完了とするか

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 対象システムと、関与していると思われるベンダー | 分かる範囲でよい。抜けは調査で埋める |
| 契約書の所在 | 原本／写し／電子。管理部門、共有フォルダの場所 |
| 支払実績データの入手可否 | 会計システムから取得できるか、誰に依頼すればよいか |
| 整理が必要になった背景 | 更新時期、監査対応、担当者交代、コスト削減要請 |
| いつまでに整理が必要か | 日付とその根拠 |
| 過去に整理を試みたか | ある場合、その資料と、途中で止まった理由 |

**添付を依頼するもの**：契約書（見つかる範囲すべて）、支払実績データ、システム構成図

**回答が薄いときの追い方**：契約書が揃わないことを前提に進める。**支払実績から契約の存在を逆算する**ほうが確実である。

<br>

### A.4.9 体制・数量が実態に合っていない

**確定させたいこと**：ずれの方向と大きさ、そして変更可能な時期

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| どの指標でずれていると判断したか | 実績データか、現場の感覚か |
| 利用実績の推移 | 直近12ヶ月以上。ライセンス数、問い合わせ件数、処理量など |
| 契約上の数量・上限 | 契約書上の数値と、超過時の扱い |
| 必要と考える水準 | 増やす／減らす、その目標値と根拠 |
| 変更が可能になる時期 | 契約期間中に変更できるか、更新日を待つ必要があるか |
| 業務側の変化 | 組織変更、業務量の変化、他システムへの移行 |

**添付を依頼するもの**：利用実績データ、現行契約書（数量・変更条項を含む）

**回答が薄いときの追い方**：縮小の相談は先送りされやすい。過剰分が月あたりいくら流出しているかを金額で示すと、優先度が上がる。

<br>

### A.4.10 継続か切替かの判断

**確定させたいこと**：判断の期限（＝解約通知期限）と、比較すべき軸

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| **契約満了日と解約通知期限** | 最優先。契約書の該当条項を確認して記入してもらう |
| 迷っている理由 | 価格／品質／技術の陳腐化／体制の不安／担当者との関係 |
| 現行ベンダーで満足している点 | 切替で失うものを把握するため |
| 許容できる業務停止時間 | 切替時の停止をどこまで許容できるか |
| 移行に使える自社要員と期間 | 人数と、確保できる期間 |
| 現行ベンダーに検討を伝えてよいか | 可／不可。時期も含めて |
| 過去の切替経験 | 他システムでの切替実績と、そのときの所要期間 |

**添付を依頼するもの**：現行契約書、直近のSLA報告書、利用実績データ

**回答が薄いときの追い方**：解約通知期限が分からない場合、この確認だけを先行させる。**期限を過ぎていれば、今期の選択肢は自動更新のみ**になり、以降の検討の前提が変わる。

<br>

### A.4.11 縮小・廃止の段取り

**確定させたいこと**：もっとも早い期限（＝最短の解約通知期限）

| 記入を依頼する項目 | 記入の粒度 |
|---|---|
| 廃止・縮小の予定日 | 決定済みか、検討中か |
| 関与している契約の一覧 | 保守、ライセンス、回線、監視、クラウド利用料。**周辺契約が漏れやすい** |
| 各契約の満了日と解約通知期限 | 分かる範囲で。**最も早い期限が実質的な決定期限になる** |
| 残すべきデータと保存期間 | 法令・監査要件の有無。所管部門への確認状況 |
| 後続システムの有無 | ある場合、稼働時期と並行期間の要否 |
| 前払いしている費用の有無 | 年額前払い、複数年一括払いなど |

**添付を依頼するもの**：関連する契約書すべて、直近の請求実績、システム構成図

**回答が薄いときの追い方**：契約の一覧が出てこない場合、A.4.8（契約の棚卸し）を先に実施する。棚卸しなしに廃止を進めると、必ず解約漏れが出る。

<br>
