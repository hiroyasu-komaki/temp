# 契約区分の定義

第4章 4.4 ステップ3で、ベンダー分析の行ごとに付ける「区分」の定義。施策マスタ（Tier×区分）と、説明資料「来期の取り組み候補　契約区分ごとの活動」の前提になる。

## 出典

- (a)〜(e)の5区分：`02_concepts/governance/it-cost-reduction` 第5章 5.2 の区分表（内容・コスト構造）
- クラウド：本書で追加。it-cost-reduction ではクラウド領域を管掌外として扱ったため、5区分に含まれていない
- 費用区分：予算台帳（`planning/opex_budget-sheet.xlsx`）の `cost_category`

## 6つの区分

| 区分 | 含むもの | コスト構造 | 予算台帳の費用区分（初期値） |
|---|---|---|---|
| (a) ライセンス・SaaS | パッケージ／SaaSのライセンス・サブスクリプション費。ERP、CRM、HCM、ITSMなど、ユーザー単位・従業員単位の継続課金 | 席数×単価。値上げは更新のタイミングに集中し、ベンダー主導で起きる | SaaS / License |
| (b) 運用保守委託 | 既存システムの運用保守委託費。SIerへの年間保守契約 | 人月単価×要員数 | Outsourcing |
| (c) 開発・改修 | 開発・改修プロジェクト費。単年度の投資的支出 | 案件ごとの見積もり。人月単価の上昇が効く | Outsourcing（案件の予算行を手で振り替える） |
| (d) ミドルウェア・DB | ミドルウェア／データベースのライセンス・保守費。Oracle Database、Java、アプリケーションサーバーなど | ライセンス＋年間保守料。ライセンス体系が複雑 | SaaS / License、Maintenance（該当する行を手で振り替える） |
| (e) オンプレ維持 | オンプレ資産の維持費。ハードウェア保守、データセンター費用、回線費用 | 機器の保守料・ラック費用・回線費用 | Maintenance、Hardware、Telecom |
| クラウド | IaaS／PaaSの利用料（AWS、Azure、GCPなど）。コミット契約と従量課金 | 利用量×単価。コミット額（上乗せ幅・繰越・サービス横断の消化）で決まる | Cloud |

## 区分の境界（迷ったときの判断）

| 迷う組み合わせ | 判断 |
|---|---|
| (a) とクラウド | 業務アプリとして使うもの（SaaS。Microsoft 365 を含む）は (a)。システムの基盤として使うもの（IaaS／PaaS）はクラウド |
| (a) と (d) | 業務アプリのライセンスは (a)。業務アプリを動かす基盤のミドルウェア・DBのライセンスと保守は (d) |
| (b) と (c) | 継続して結ぶ年間の保守契約は (b)。案件ごとの単年度の支出は (c) |
| (d) と (e) | ソフトウェアのライセンス・保守は (d)。機器の保守、データセンター、回線は (e) |

- 区分は費用区分からの初期値で、行ごとに修正できる（第4章 4.4 ステップ3）。(c) と (d) は費用区分だけでは見分けられないため、ベンダー分析で手で振り替える。
- 人件費・減価償却・出張研修・社内費用は、ベンダー取引ではないため区分を付けない（第4章 4.4 ステップ1で除く）。

## 確認が必要な点

- クラウドの定義と、上の境界の判断は本書で新しく置いたもの。IT担当者・調達部門と合意する。
- 母集団ファイル（サンプル）では、Benchling（ELN、費用区分 Maintenance）が (e) オンプレ維持になっている。SaaSであれば (a) が正しい。
- 施策マスタの区分には (a)〜(e) の記号があり、クラウドにはない。記号を付けるか、すべて外すかを揃える。
