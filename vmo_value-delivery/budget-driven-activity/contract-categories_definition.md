# 契約区分の定義

第4章 4.4 ステップ3で、ベンダー分析の行ごとに付ける「契約区分」の定義。第4章 4.5、施策マスタ（契約区分×シナリオ）、説明会資料（`proposal/vmo-briefing_v2.pptx` 13枚目「6つの契約区分」と16〜21枚目）の前提になる。

## 出典

- ライセンス・SaaS〜オンプレ維持の5区分：`02_concepts/governance/it-cost-reduction` 第5章 5.2 の区分表（内容・コスト構造）
- クラウド：本書で追加。it-cost-reduction ではクラウド領域を管掌外として扱ったため、5区分に含まれていない
- 費用区分：予算台帳（`planning/opex_budget-sheet.xlsx`）の `cost_category`

## 6つの区分

| 契約区分 | 含むもの | コスト構造 | 予算台帳の費用区分（初期値） |
|---|---|---|---|
| ライセンス・SaaS | パッケージ／SaaSのライセンス・サブスクリプション費。ERP、CRM、HCM、ITSM、Microsoft 365 など、ユーザー単位・従業員単位の継続課金 | 席数×単価。値上げは更新のタイミングに集中し、ベンダー主導で起きる | SaaS / License |
| 運用保守委託 | 既存システムの運用保守委託費。SIerへの年間保守契約 | 人月単価×要員数 | Outsourcing |
| 開発・改修 | 開発・改修プロジェクト費。単年度の投資的支出。システムの開発・改修案件、法改正や製品の保守終了への対応 | 案件ごとの見積もり。人月単価が効く | Outsourcing（案件の予算行を手で振り替える） |
| ミドルウェア（DB・運用管理・連携） | データベース・運用管理・データ連携のライセンス・保守費。Oracle Database、Java、アプリケーションサーバー、JP1、DataSpider など | ライセンス＋年間保守料。ライセンス体系が複雑 | SaaS / License、Maintenance（該当する行を手で振り替える） |
| オンプレ維持 | オンプレ資産の維持費。ハードウェア保守、データセンター費用、回線費用 | 機器の保守料・ラック費用・回線費用 | Maintenance、Hardware、Telecom |
| クラウド | IaaS／PaaSの利用料（AWS、Azure、GCP などの基盤サービス）。コミット契約と従量課金 | 利用量×単価。コミット額（上乗せ幅・繰越・サービス横断の消化）で決まる | Cloud |

## 区分の境界（迷ったときの判断）

| 迷う組み合わせ | 判断 |
|---|---|
| ライセンス・SaaS とクラウド | 業務アプリとして使うもの（SaaS。Microsoft 365 を含む）はライセンス・SaaS。システムの基盤として使うもの（IaaS／PaaS）はクラウド |
| ライセンス・SaaS とミドルウェア | 業務アプリのライセンスはライセンス・SaaS。業務アプリを動かす基盤（データベース・運用管理・データ連携）のライセンスと保守はミドルウェア |
| 運用保守委託と開発・改修 | 継続して結ぶ年間の保守契約は運用保守委託。案件ごとの単年度の支出は開発・改修 |
| ミドルウェアとオンプレ維持 | ソフトウェアのライセンス・保守はミドルウェア。機器の保守、データセンター、回線はオンプレ維持 |

- 区分は費用区分からの初期値で、行ごとに修正できる（第4章 4.4 ステップ3）。開発・改修とミドルウェアは費用区分だけでは見分けられないため、ベンダー分析で手で振り替える。
- 人件費・減価償却・出張研修・社内費用は、ベンダー取引ではないため区分を付けない（第4章 4.4 ステップ1で除く）。

## 確認が必要な点

- クラウドの定義と、上の境界の判断は本書で新しく置いたもの。案件担当・調達部門と合意する。
- 母集団ファイル（サンプル）では、Benchling（ELN、費用区分 Maintenance）がオンプレ維持になっている。SaaSであればライセンス・SaaSが正しい。
- 本書・第4章・説明会資料は区分に記号（a〜e）を付けていない。施策マスタと母集団ファイルの列「区分（a〜e）」に残っている記号を外して揃える。
