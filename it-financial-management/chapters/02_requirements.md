## 1. 位置づけ

本書は、`01_policy.md` のフェーズ1として、**日本リージョンの予実管理・着地見込み管理の標準プロセス**の要件を定める。業務フロー（4章）とデータの持ち方（5章）は、日本で現在実際に行っている運用を書き起こしたものである。

月次で次のことができること。

- **予実管理**：締まった月の実績を予算と対比し、差異とその理由（Rationale）を把握する
- **着地見込み管理**：「実績累計＋残りの月の予測」で期末の着地を見込み、年間予算との差を把握する
- **予算番号の適正化の管理**：予算番号が設定されていない予算・実績の金額と、その減り具合を把握する

予算の策定、ドライバー（契約・資産・要員）からの予算計算、チャージバック／ショーバック、北米・EMEAへの展開（フェーズ2）は扱わない。

## 2. 前提

### 2.1 システム

| システム | 役割 | この業務との関係 |
|---|---|---|
| D365（ERP） | 財務会計。月次で実績を締める | 実績の発生源 |
| Tagetik（EPM） | 予算を保持する。D365から総勘定元帳データが月次バッチで連携される | 予算と実績の正本。予算と実績は**別々のファイル**としてExcelでダウンロードする |

- Tagetikはユーザーの編集をExcel経由で行う。
- **Tagetikは予測値を保持できない**。予実管理表に予測値を入れても、月次で実績が更新されると予測部分がクリアされる。そのため、**予測値とRationaleはTagetikの外（Excel）で保持する**。

### 2.2 対象リージョン

- 日本リージョンのみを対象とする。予算・実績ともリージョンコードを持つので、日本の明細だけを取り出して扱える。

### 2.3 予算番号の現行ルール

日本には、予算番号の従属項目として **Department**（インフラ、アプリ、セキュリティ、データ、ガバナンスのチーム名）がある。予算番号についてのルールは次のローカルルールだけである。

| ルール | 内容 |
|---|---|
| 桁数 | 4桁 |
| 先頭1桁 | Departmentを識別できるようにする |
| 先頭1桁「7」 | 例外コード |
| 先頭1桁「9」 | 経理が使用するため利用しない（グローバルルール） |

Departmentごとに採番する以外に、何を1つの予算番号とするか（採番の単位）は決まっていない。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 予算番号 | 予算を塊として管理するための4桁のコード |
| Department | 予算番号の従属項目。インフラ、アプリ、セキュリティ、データ、ガバナンスのチーム。予算番号の先頭1桁で識別する |
| 予測値 | まだ締まっていない月について、予算管理者が見込む金額 |
| 着地見込み | 実績累計（締め月まで）＋予測値（残りの月）の合計 |
| Rationale | 予実差異・着地差異の理由 |
| 予算データ・実績データ | Tagetikから別々にダウンロードした予算と実績のファイル |
| 更新用予実管理ファイル | 予算データと実績データを予算番号で統合し、前月の予測値・Rationaleを転記したExcel。予算管理者が更新する |
| バックアップ | 月次報告後の更新用予実管理ファイルを、翌月の転記元として保管したもの |

## 4. 業務フロー（月次）

日本で現在行っている流れである。

| # | 作業 | 担当 | 入力 → 出力 |
|---|---|---|---|
| 1 | D365で月次の実績を締める | 経理 | — |
| 2 | D365からTagetikへ実績が連携される | （自動バッチ） | 総勘定元帳データ |
| 3 | Tagetikから予算データと実績データを別々にダウンロードする | ITファイナンス | Tagetik → 予算データ・実績データ |
| 4 | 予算データと実績データを予算番号で1つにまとめ、前月のバックアップから予測値とRationaleを転記する | ITファイナンス | 予算データ＋実績データ＋前月バックアップ → 更新用予実管理ファイル |
| 5 | 更新用予実管理ファイルをGDS内の予算管理者に展開する | ITファイナンス | — |
| 6 | 実績を確認し、Rationaleを入力し、予測値を更新する | 予算管理者 | 更新用予実管理ファイル（更新済み） |
| 7 | 月次報告に使う | ITファイナンス | 月次報告 |
| 8 | 翌月に使うため、バックアップフォルダに格納する | ITファイナンス | バックアップ（当月版） |

バックアップはExcelファイルのまま保管する（Power BIは使わない）。

## 5. データ要件（更新用予実管理ファイル）

### 5.1 行（キー）

- リージョン＋予算番号を1行とする（勘定科目を付帯情報として持つ）。リージョンはフェーズ1では日本だけだが、フェーズ2に備えて項目として持つ。
- キーはTagetikの予算データ・実績データに含まれる項目をそのまま使い、独自のコードやマスタは作らない。
- 予算データと実績データはキーで1つにまとめる。予算だけの行も、実績だけの行（予算のない実績）も残す。予算のない実績は確認対象として目印を付ける。

### 5.2 予算番号が設定されていない明細

- 予算と実績の突き合わせは予算番号で行う。ただし現状は、予算・実績とも多くの明細で予算番号が空白になっている。
- 予算番号が空白の明細は捨てずに、「予算番号未設定」の1行にまとめて予実の対象に含める。これにより、総額は予算番号の設定状況にかかわらずTagetikと一致する。
- 予算番号未設定の明細は、勘定科目ごとの内訳を一覧で確認できるようにする（どこから設定を直すべきかを見るため）。
- 予算番号の設定はTagetik（またはD365）の側で直す。更新用予実管理ファイルの中で予算番号を補ったり付け替えたりはしない。
- 予算番号未設定の行にも予測値を入れ、着地見込みに含める。

### 5.3 列

| 区分 | 内容 |
|---|---|
| キー | リージョン、予算番号、（付帯）勘定科目・名称など、予算データ・実績データに含まれる項目 |
| 月別 | 予算、実績（締め月まで）、予測値（未締め月） |
| 年間 | 年間予算、実績累計、予測値合計、着地見込み、着地差異（着地見込み−年間予算） |
| 理由 | 当月の予実差異のRationale、着地差異のRationale |

### 5.4 転記のルール

- 前月のバックアップから、**同じキーの行**の予測値とRationaleを転記する。
- 新しく締まった月の予測値は実績で置き換わる。
- 前月のバックアップにない行（新しい予算番号）は予測値を空欄とし、予算管理者が入力する対象として目印を付ける。
- 前月にあって当月の予算データ・実績データのどちらにもない行は、転記漏れを防ぐため一覧で確認できるようにする。

### 5.5 版

- 更新用予実管理ファイルは月ごとに1ファイルとし、ファイル名に年月を入れる（例：`gds_forecast_YYYYMM.xlsx`）。
- 前月の着地見込みとの比較には、前月のバックアップを使う。

### 5.6 予算番号の運用ルール

予算番号のルールは、あるべき論から先に決めず、毎月の予実管理を回しながら実務の中で固める（`01_policy.md` 3章）。フェーズ1では次を守り、固まったものから本節に書き足す。

- 現行のルール（2.3）を守る。先頭1桁「9」は使わない。
- 予算番号はTagetik（またはD365）で設定し、予算と実績の両方に付ける。
- 予算番号未設定の明細（5.2）を設定するたびに、何を1つの予算番号としたか（採番の単位）を記録し、ルールとして固める。
- 例外コード（先頭1桁「7」）を使ったときは、理由を記録する。

固めるべきルールの中身は未確定事項9〜12に挙げる。

## 6. 出力要件

次の5つを確認できること。

| # | 出力 | 内容 |
|---|---|---|
| 1 | 当月の予実差異 | 当月の予算と実績の差、Rationale |
| 2 | 累計（YTD）の予実差異 | 期首から締め月までの予算累計と実績累計の差 |
| 3 | 着地差異 | 着地見込みと年間予算の差、Rationale |
| 4 | 前月見込みとの比較 | 当月の着地見込みと前月の着地見込みの差 |
| 5 | 予算番号の設定状況 | 予算番号未設定の予算額・実績額と、全体に占める割合（設定率）。前月版と比べて進み具合を見る |

合計は円で出す。円以外の通貨で計上された明細は、為替レート表（予算レートと月別レート）を使って円に換算してから合計する。また、円の金額を外貨に換算する逆方向の換算（例：円の総額をUSDで示す）もできること。各予算番号の行は計上された通貨のまま表示する。

## 7. 対象外

- 予算の策定・入力（予算はTagetikで管理する）
- 契約・固定資産・要員から予算を計算する仕組み
- 北米・EMEAへの展開と、3リージョンの統合（フェーズ2）
- チャージバック／ショーバック
- Power BIによる保管・可視化

## 8. 未確定事項

| # | 事項 |
|---|---|
| 1 | 予測値を月別で入れるか、残りの期間の合計で入れるか |
| 2 | Tagetikの予算データ・実績データの列構成（ダウンロード形式） |
| 3 | 手順4の転記を手作業で行うか、Excelの機能（Power Queryなど）で自動化するか |
| 4 | Rationaleを求める差異の閾値（率・金額） |
| 5 | 期中に予算が修正された場合の扱い |
| 6 | 月次報告の様式と報告先 |
| 7 | 予算番号未設定の行の予測値を誰が入力するか |
| 8 | 予算番号の適正化の目標（いつまでに設定率をどこまで上げるか）と、Tagetik／D365側で設定を直す担当 |
| 9 | 採番の単位（何を1つの予算番号とするか。例：契約、システム、プロジェクト） |
| 10 | Departmentと先頭1桁の対応（例：1＝インフラ） |
| 11 | 例外コード（先頭1桁「7」）を使ってよい条件 |
| 12 | 予算番号の採番・変更・廃番の責任者と手続き |
| 13 | 予算レートと月別レートの使い分け（予算・予測・実績をそれぞれどちらで換算するか）、レートの入手元、期中に改定された場合の扱い。逆方向の換算に、公表されている別のレートを使う必要があるか |

北米・EMEAに関する事項は `01_policy.md` 5章に置く。
