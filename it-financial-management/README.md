# IT Financial Management（GDS予実管理）

GDSの予算について、毎月の予実管理と、それをもとにした期末の着地見込み管理を整備するための資料です。予算と実績の正本はTagetikにありますが、Tagetikは予測値を保持できないため、予測値と予実差異の理由（Rationale）はExcelの更新用予実管理ファイルで持ち、月ごとに保管して翌月に引き継ぎます。予算の策定やチャージバック／ショーバックは扱いません。

この取り組みには、予算番号の適正化、北米・EMEAへの展開、予算番号の共通ルール化という3つの目的があります。まず日本リージョンで、今行っている予実管理を標準プロセスとして固め（フェーズ1）、そのうえで北米・EMEAに展開して3リージョンを統一します（フェーズ2）。予算番号のルールは、あるべき論から先に決めるのではなく、日本で毎月の運用を回しながら実務の中で固めていきます。

```
it-financial-management/
├─ README.md                  … このファイル
├─ .gitignore
├─ chapters/
│   ├─ 01_policy.md           … 方針書（背景・3つの目的・フェーズ分け・フェーズ2で決めること）
│   ├─ 02_requirements.md     … 業務要件定義書（フェーズ1：日本の標準プロセスの要件）
│   └─ 03_design.md           … 設計書（業務フロー・機能配置・テーブル定義とER・DFD）
├─ proposal/
│   └─ it-financial-management_proposal.pptx … 取り組みの概要スライド（10枚）
├─ template/
│   └─ gds_forecast_template.xlsx  … 更新用予実管理ファイルの雛形（テーブル定義どおりの列と、サンプル1行）
└─ appendix/
    ├─ A_architecture-decisions.md … アーキテクチャ決定記録（ADR）
    └─ B_record-image.html         … レコードイメージ（各テーブルのサンプル行と流れ。ブラウザで開く）
```

はじめて読む場合は、方針書（`01_policy.md`）で全体の狙いと進め方をつかんでから、要件定義書と設計書に進んでください。3つの文書はいずれもMarkdownが正本です。設計上の大きな決定（予測値の正本をExcelにする、など）の理由は、付録のADRに残しています。設計書の図はMermaidで書いているので、対応したMarkdownビューアで図として表示されます。要件定義書の未確定事項は設計書で仮置きしているので、決まったら両方を直してください。
