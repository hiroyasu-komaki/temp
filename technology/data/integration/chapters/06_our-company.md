# 06 データ連携：当社の現状

> 当社固有の情報は、このトピックではこのファイルにだけ書く。01〜05章は一般論として書く。

## 要旨

SAP SuccessFactors 用の中継サーバとして DataSpider を構築することが決まっている（データハブサーバ構築プロジェクト）。人事情報を扱うため、中継サーバ上にデータを保持しない設計。ERP・CRM の置き換え検討と、旧生産管理システム（mcframe）に残る連携の付け替えも、この連携基盤の使い方に関わる。

## 現在の構成

| 対象 | 使っている製品・仕組み | 範囲・備考 |
|---|---|---|
| 人事系の連携 | DataSpider（構築中） | SuccessFactors と人事系の他機能（多くは SaaS や Web 系サービス）をつなぐ中継サーバ。データは保持しない設計。製品は DataSpider Cloud の見込みだが未決定 |
| mcframe 経由の連携 | mcframe | D365 稼働後、mcframe の機能はほとんど使われていないが、統合マスタとのインターフェースや、mcframe 経由で連携していたレガシーシステムとの連携が残っていると想定 |
| ERP | Microsoft Dynamics 365 | 置き換えを再評価する予定（ERP は未定） |
| CRM | Veeva CRM（Salesforce 基盤） | EOL により置き換えが必要。Veeva の移行支援は他社システムとの連携を対象外としているため、ERP などとの連携は作り直しになる |
| 品質・薬事など | Veeva Vault | 維持する方針 |

## 経緯

- データハブサーバの構築プロジェクトが進行中。SuccessFactors の中継サーバとしての構築は決定済み。

## 懸念と論点の対応

| 懸念（誰の） | 04章の論点 |
|---|---|
| 人事情報を中継サーバに保持したくない（人事系連携の設計方針） | 論点6：データを中継するだけか、溜めるか |
| 人事用と ERP・製造（GxP）用を同じ環境に置くか | 論点4：1つのインスタンスにまとめるか、分けるか、論点8：規制対象のデータを流すか |
| ERP が未定のまま、CRM の連携を作り直す必要がある | 論点2：ERPベンダーの製品か、中立の製品か |
| SaaS の中身がブラックボックス、事業継続をベンダーに委ねたくない（CIO。ERP についての懸念だが、連携基盤にも同じ構図がある） | 論点3：ベンダーが管理するか、自社が管理するか |
| 拠点（日本・北米・欧州）をまたぐ場合の置き場所、欧州の個人データ | 論点5：どこに置くか（地域） |

## 進行中の検討

- **インスタンス**：人事用と、ERP・製造（GxP）用でインスタンスを分ける方向。
- **mcframe**：入れ替えか載せ替えかを検討することになっている。残っている連携を移したうえで廃止する案もある。残っている連携の移し先として、この連携基盤が候補になる。
- **CRM・ERP**：置き換えに伴う連携の作り直しを、この連携基盤の上で行うかどうか。

## 未確認の事項

- 「中継サーバの構築」が、自社管理型（DataSpider Servista をサーバに導入）と、クラウド型（DataSpider Cloud）のどちらを指すか
- DataSpider Cloud の製品ロードマップ（同社が現在 iPaaS として前面に出しているのは HULFT Square）
- 「データを保持しない」の範囲（一時ファイル、ログ、再実行用データ、バックアップ）
- mcframe に残っている連携の実態（インターフェースやジョブの実行履歴、ネットワークの接続先で確認する）
- 拠点ごとのシステム（D365 など）の配置と、連携が地域の中で完結するかどうか
- インスタンスを分けた場合のライセンス費用
