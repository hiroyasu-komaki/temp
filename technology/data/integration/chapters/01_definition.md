# 01 データ連携の定義と範囲

## 要旨

データ連携（システム間連携）は、別々のシステムの間でデータを受け渡し、形式を変換し、処理の順序を制御する仕組みである。連携をシステムごとに個別に作るのではなく、**連携専用の基盤（ハブ）に集める**のが現在の主流で、その基盤をクラウドサービスとして提供するものを **iPaaS** と呼ぶ。

## 定義

- **データ連携**：あるシステムのデータを、別のシステムが使える形で届けること。受け渡し（転送）、変換（形式・コード・項目の読み替え）、制御（起動のきっかけ、順序、分岐、再実行）からなる。
- **iPaaS（Integration Platform as a Service）**：システム連携の基盤を、ベンダーが管理するクラウドサービスとして提供するもの。社内とクラウドにまたがるアプリケーション・サービス・データの間の連携を、実装・実行・監視できる。かつて社内サーバで動かしていた EAI・ESB（企業内のシステム連携ミドルウェア）の役割を、クラウドで担う。

## 成り立ち

| 段階 | 方式 | 特徴 |
|---|---|---|
| 個別連携 | システム同士を1本ずつ直接つなぐ（ポイント・ツー・ポイント） | 少数なら簡単。システムが増えると、つなぐ本数がシステム数の2乗に近い勢いで増え、どこで何がつながっているか分からなくなる |
| EAI・ESB | 社内サーバに連携ミドルウェアを置き、ハブとして集約する | 各システムはハブとだけつながる。連携を一元管理できる |
| iPaaS | 連携基盤をクラウドサービスとして使う | SaaS が増え、社内とクラウドをまたぐ連携が中心になったことに対応。基盤の運用をベンダーに任せられる |

ハブを置く最大の理由は、**変更の影響を閉じ込める**ことにある。各システムがハブとだけつながっていれば、あるシステムを入れ替えても、作り直すのはハブとそのシステムの間の接続だけで済む。

## 連携の方式

| 方式 | 中身 | 向いている用途 |
|---|---|---|
| ファイル転送 | ファイルを安全・確実に送り届ける | 大量データの定期的な受け渡し、社内システム間 |
| バッチ連携（ETL） | データを抽出し、変換して、まとめて書き込む | 夜間の一括処理、マスタの定期配信 |
| API連携 | 相手のAPIを呼び出して、その場でデータを渡す・受け取る | 即時性が必要な処理、SaaS との連携 |
| イベント連携 | 「何かが起きた」という通知をきっかけに処理を動かす | 発生した事象にすぐ反応したい処理（例：逸脱の起票 → 出荷保留） |

## 範囲（何であり、何でないか）

| 含むもの | 含まないもの（隣接領域） |
|---|---|
| データの受け渡し、形式の変換、処理の制御 | どのシステムのデータが正かを決めること（マスタデータ管理） |
| 社内システム・クラウド・SaaS をまたぐ接続 | 分析のためにデータを蓄積すること（DWH・データレイク） |
| 実行の記録、エラー通知、再実行 | 業務のロジックそのもの（各業務アプリケーションが持つ） |
| | APIの公開・利用者管理・流量制御（API管理。製品によっては iPaaS に含む） |

## 用語集

| 用語 | 意味 |
|---|---|
| EAI | Enterprise Application Integration。企業内のアプリケーション同士をつなぐ連携基盤 |
| ESB | Enterprise Service Bus。サービス同士を共通の「バス」を介してつなぐ連携基盤の方式 |
| iPaaS | Integration Platform as a Service。クラウドで提供される連携基盤 |
| ETL／ELT | Extract・Transform・Load。抽出・変換・書き込み。ELT は書き込んでから変換する |
| コネクタ（アダプタ） | 特定のシステムや形式（DB、ファイル、SaaS、REST API など）に接続するための部品 |
| マッピング | 送り元と送り先の項目の対応づけと、値の変換 |
| エージェント | 社内ネットワークに置き、クラウドの連携基盤から社内システムへ安全に接続するための中継プログラム |
| REST API／OData | Webの仕組みでデータをやり取りするための代表的な方式。OData は SAP や Microsoft の製品で多く使われる |
| インターフェース台帳 | どのシステムからどのシステムへ、何のデータを、どの方式・頻度で流しているかの一覧 |
