PROPOSAL

IT Materiality フレームワーク ─ 外部性を測り、所有し、予算に接続する

前頁までに、分権的IT投資の下で生じる4つの症状は、いずれも意思決定者の視野の外に便益・費用が漏れることから演繹されることを確認した。
経済学が示す処方箋は、意識改革ではなく①測定　②所有権の設定　③インセンティブの再設計である。本フレームワークは、この三点を制度として実装する。

01設計要件と、それに対する回答
要件1測定
外部性は当事者から見えない。見えないものは判断の場に上がらない。まず視野の外に出た便益・費用を可視化する尺度が要る。
FRAMEWORK ANSWER投資判断に第3の軸
「共通性・持続性」を導入する
要件2所有権
共通基盤・アーキテクチャ健全性に所有者がいない。所有者がいなければ、誰も測らず、誰も供給せず、誰も請求できない。
FRAMEWORK ANSWERIT部門を共通層のオーナーとし、
測定責務と起案権を負わせる
要件3インセンティブ
尺度を作っても、予算の出所と決定権が変わらなければ判断は変わらない。評価軸は判断者の利害を動かさないからである。
FRAMEWORK ANSWERMateriality の判定を
予算配分プロセスに接続する

03要件1への回答 ─ 投資判断の第3の軸
既存の2軸は、いずれも単一施策を、それ単独で、当期の視点から評価する静的な軸である。この2軸だけでは、外部性を持つ投資は構造的に評価から脱落する。
軸1事業価値
やれば、何が得られるか？
売上・生産性・コスト削減／戦略との整合性／ROI・NPV
脱落するもの：便益が自部門の外に及ぶ投資は、自部門の取り分だけでは常に過小評価される。
軸2リスク低減・法規制対応
やらなければ、何を失うか？
法令・規制対応／セキュリティ／事業継続・可用性
脱落するもの：EOL・技術的負債は「発生確率が低い」と評価されるため、毎年、優先順位で負け続ける。
軸3共通性・持続性NEW
この投資の便益・費用は、どこまで自部門・当期の外に及ぶか？
判断基準 判定者 導入
受益範囲（利用部門・利用者数・対象業務） 申請者
＝事実申告		 初年度
不作為時の将来費用増分（EOL・保守費・移行難度） IT部門 初年度
他施策の前提依存度（この投資なしに実行不能な計画数） IT部門 次年度〜
標準からの逸脱度（将来の全社費用への転嫁） IT部門 次年度〜
設計原則：スコアは申請者に付けさせない。依存関係・EOL・標準は事業部門から原理的に見えず、かつ評価が予算に直結する以上、自己申告には必ずバイアスがかかる。申請者に求めるのは「事実」、スコア化するのは IT部門。
04要件2への回答 ─ 共通層のオーナーを定める
IT部門を「共通層のオーナー」として定義する
共通基盤・アーキテクチャ健全性・共有資源に所有者がいないことが、放置の直接の原因である。したがって本フレームワークは、IT部門に次の責務と権限を同時に付与する。

【責務】全社の技術資産の状態を把握し、外部性を測定する唯一の主体となる（EOL台帳・アーキテクチャ標準・依存関係の保持）
【権限】共通性・持続性スコアを付与し、共通層への投資を自ら起案できる
なぜ IT部門でなければならないか
外部性とは、当事者から見えない便益・費用のことである。見えない者に測らせるのは論理的に矛盾する。全部門のシステム・依存関係・保守状況を横断的に見ている主体は、組織上IT部門のみである。

裏を返せば──この軸を導入するとは、IT部門が「全社の技術資産の状態を把握している唯一の主体」になると約束することに等しい。台帳を持たなければ、この枠組みは成立しない。

9. IT部門による起案
全社基盤（ID管理・データ基盤・統合基盤）はどの部門も申請しないため、救済枠には載ってこない。IT起案枠がなければ、正の外部性の問題は解けない
救済枠の定義を、最初に宣言する：救済枠は「惜しかった案件の敗者復活」でも「政治的配慮の調整弁」でもない。事業部門の視野では正当に評価できない案件を、全社視点で拾い直すための枠である。この定義を先に固定しなければ、救済枠は必ずごね得ルートに変質する。
06段階導入 ─ 判定機構であると同時にデータ収集機構である
台帳が整っていないことは制約であるが、同時に台帳を作るための唯一の機会でもある。精緻な尺度を待つのではなく、粗い判定から始めて台帳を育てる。
PHASE 1 ／ 初年度
台帳なし ─ 2問判定で始める
・共通性は「基盤性」「負債」の2問でIT部門が仕分ける
・スコアの厳密さは求めない。判定理由の記録を必須とする
・事業部門からはスコアではなく事実を集める
・集まった申請書の束が、そのまま台帳の初版になる

結び ─ このフレームワークが本質的に行っていること
IT Materiality フレームワークは、投資評価表の項目を増やす取り組みではない。分権的IT投資が構造的に取りこぼしてきた「視野の外の便益・費用」を、測定可能にし、所有者を定め、予算配分に接続する制度である。
経済学が外部性に対して処方してきたもの──測定（内部化）、所有権の設定、公的供給──を、企業内部の予算制度に翻訳したものにほかならない。
導入にあたっての留意：本フレームワークは、次の二つが揃わなければ形骸化する。
① IT部門が台帳を持つこと。測定責務を負う以上、台帳のない状態は約束不履行である。初年度は粗くてよいが、育てる計画がなければならない。
② 救済枠とIT起案枠の両方が確保されること。救済枠のみでは「負債が溜まる」しか解けず、「基盤が育たない」は次年度も繰り返される。
